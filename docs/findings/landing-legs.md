# Landing legs (landing gear) in 1.163

Status: read in Ghidra 2026-10-21 [code] unless marked; data from `hf_ml/data/Libraries/OL.seria` [file] and the sim.24 telemetry `hf_ml/data/sim_runs10/hf_ally_simparts_*.csv` [game]. The question was whether folded legs are non-colliding. They are NOT: no code removes or filters their fixtures. Related: [ship-bodies-fixtures-and-breakup.md](ship-bodies-fixtures-and-breakup.md), [contact-damage-and-fire.md](contact-damage-and-fire.md).

## Which parts are legs
* Stats `OL.seria`: `MDL_LEG_01` (price 50, power 50, `m_mdl_leg_force` 100), `MDL_LEG_02` (100, 100, 400), `MDL_LEG_03` (200, 200, 1600), `MDL_LEG_04` (400, 400, 3200); all category `m_category=8192` (0x2000), armour 5, power priority 2 [file]. Slot types: `MDL_LEG_01` = 266, `MDL_LEG_02` = 282 (JOINTED, own b2 bodies) [game]. `ITEM_LEG` is the shop item (constructor.seria).
* Part logic id (`+0x3c4`, `m_logic`) = **400 (0x190)** for a leg part; `+0x7b0` (`is_leg`) is the Body flag the contact code tests [code].
* Layer (`+0x1f0`, `m_layer`) of leg parts = **7** in the telemetry; hull/armour/structure 1, ammo/fuel/generator/static engine 2, bridge and aircraft 3, swivel engines 4, cannons 6 [game, sim_runs10 M rows]. Shells are created with layer 15 (`BulletImpact__` `0x140052b2e`) [code].
* Structure (Lightning, sim_runs10 J rows): each leg is two parts joined by revolute joints with angle limits [0, 1.9635] / [-1.9635, 0] (112.5 degrees), reference angle +-1.1781 (67.5 degrees), plus a distance joint (kind 0, "rope" length stored at Joint `+0xd8/+0xdc`) and weld joints (kind 2); the revolute motors are DISABLED in the logged rows (passive until the logic enables them) [game].

## State machine (creatureLogic `0x140033b90`, leg case at `0x14003878f..0x140038b71`) [code]
* Leg part state is `part+0x3cc`: **0 = retracting, 1 = retracted (folded), 2 = deploying, 3 = deployed**. The owner creature keeps an aggregate mode in `creature+0xb48` (same values: 0/1/2/3; set to 1 when retracted, 3 when deployed).
* States 0 and 2 drive the leg's revolute joint (the joint whose node B `+0x88` is this part): the target is one of the joint's two limits (`Joint+0xfc` lower or `+0x100` upper, chosen by the `cw` flag `Joint+0x110`: deploy and retract use opposite limits). Error = `b2RevoluteJoint_GetJointAngle` (`0x14031c200`) minus target; while |error| >= a threshold (float at `0x14035278c`) `Joint_SetMotor(joint, +-speed, torque)` runs (speed constants `0x140354928` / `0x1403527a4`, torque from `0x140048780(part)` = the part's leg force term).
* When the target is reached the motor is switched off (`Joint_SetMotor(joint, 0, 0)`). **Correction 2026-10-22: `b2Joint +0x80` of a b2 distance joint is the FREQUENCY (Hz), not the length** (the length is `+0xa4`); see section 'Joint model' below: retracted arrival sets the strut frequency to 10.0 Hz, deployed arrival to `clamp(creature+0x15b8 / (leg force * 1000), 3.0, 10.0)`, and while moving it is 1.0.
* Part command id 10 with argument 1 or 3 sets the state (`Part_HandleCommand` `0x1400533f0`, only for parts with logic 400; arg 3 -> state 2 deploy, arg 1 -> retract) [code]. **Who sends command 10 (key, landing code, AI, altitude) was NOT found.**
* Initial pose: `FUN_1401bcab0` snaps each leg into the RETRACTED pose at set-up: leg angle = frame angle + joint limit (lower or upper by the `cw` flag) + reference angle, state 1, then moves the part so the joint anchors coincide and sets the rope length to 10.0 (recursive over the leg chain). `FUN_14022bc90` sets state 3 (deployed) for the landing scene. So in a battle the legs start folded (state 1) [code]; whether a mission can deploy them mid-battle is unknown.

## Collision side [code]
* Legs keep their fixtures and b2 bodies for the whole battle: nothing destroys or filters them when folded (`b2CFilter_ShouldCollide` `0x1402858c0` has no leg or state rule; folded and deployed legs collide the same). Filtering that applies to legs: layer AND (`layer_a & layer_b == 0` -> no contact; a leg (7) overlaps every other layer in use, a shell (15) overlaps all), same group/owner (`+0xc0` equal, i.e. the ship's own parts, and parent/child/grandparent pairs) never collide, so legs never touch their own hull; they DO collide with enemy ships' parts, shells and debris.
* Contact damage: `Physics_ProcessContactRecord` (`0x1402849a0`) reads `is_leg` (`+0x7b0`) of both bodies (at `0x140285043`, `0x140285084`, `0x140285685`, `0x140285771`) and the owner's byte `+0xa40`; with arcade battle active a contact involving a creature-owned leg (category 0x2000) deals no contact damage (earlier note in `hf_ml/DESIGN_NOTES.md` item 6). The exact use of `+0xa40` is unclear [guess: a "settled/landed" flag].
* Legs are ordinary damageable parts (armour 5, hp from the part): direct shell hits and blast hit them; blast area damage treats them like other non-armour parts. `ShipStatusCheck` (`0x14006ab70`) has no leg-specific rule; legs count in the part totals (`+0x16a0` / original count) like other parts [code: no leg test in the function; counting is a guess].

## For the simulator
Legs are separate b2 bodies (JOINTED slots 266/282), mass 2836 each (`MDL_LEG_01`), starting in the folded pose (state 1). Treat them as collidable small bodies that never touch their own ship; they are not "folded away". A safe simplification for battles is to keep them as fixed folded geometry only if the shells that hit them are rare; they are NOT excluded by any rule.

## Joint model for building the legs as separate b2 bodies (answer to simulator, 2026-10-22, ghidra-curator) [code]
**Data to b2.** A leg link is two `Joint` objects between the same two nodes (node A = `Joint+0x70`, node B = `Joint+0x88`; the b2 bodies are `traverseLinkedListCreature_(node)+0x178`, i.e. the Frame body for the hull side and the leg part's own body for the leg side). Joint fields (serialiser `Slot_SerializeFields` 0x1401943b0): `m_type` `+0xd0` (kind: 0 = distance strut, 1 = revolute, 2 = weld, 3 = rope), `m_render_type` `+0xd4`, `m_length` `+0xd8` (the current length, also the stored initial value), `m_length_max` `+0xdc`, `m_length_min` `+0xe0`, `shiftA` `+0xe4/+0xe8`, `shiftB` `+0xec/+0xf0`, `m_angle_enable` `+0xf4`, `m_angle_reference` `+0xf8`, `m_angle_min` `+0xfc`, `m_angle_max` `+0x100`, `m_motor_enable/torque/speed` `+0x104/+0x108/+0x10c`, `m_cw` `+0x110`. The b2 joint is built by `Joint_CreateB2Joint` 0x140193a10 and (re)built by `Joint_EnsureB2Joint` 0x140194b10, which `SomethingPreTask` calls every frame for every joint: if the cached body pointers (`+0xa8`, `+0xc0`) differ from the nodes' current b2 bodies the b2 joint is destroyed and created again (first frame, and after a tear-off or re-master). All b2 lengths are game value x 0.05.
**(i) Limited revolute (kind 1).** `b2RevoluteJointDef_Initialize` then overrides: `localAnchorA` = the world point of **shiftA through node A's transform**, `localAnchorB` = the world point of **shiftB through node B's transform** (the two pins are separate points and the solver pulls them together), both converted to body-local with the body's current rotation; `collideConnected` = false; `enableLimit = m_angle_enable`; **`referenceAngle = m_angle_reference` exactly (not angleB - angleA at creation)**; **`lowerAngle = m_angle_min`, `upperAngle = m_angle_max` exactly** (radians, unscaled, relative to the reference: b2 joint angle = angleB - angleA - reference); `enableMotor = m_motor_enable`, `maxMotorTorque = m_motor_torque`, `motorSpeed = m_motor_speed`, all raw. So the limits in the K rows are the seria values with no shift.
**(ii) Strut (kind 0): a b2 DISTANCE joint, no rope joint.** `b2DistanceJointDef_Initialize(A, B, worldAnchorA = shiftA on node A, worldAnchorB = shiftB on node B)` so the rest length at creation is the current distance between the two world anchors (b2 units); then **`frequencyHz = 10.0`, `dampingRatio = 10.0`** (the constants 0x41200000), `collideConnected` false. Two further writers change it afterwards: `Joint_UpdateLength` 0x140192f50 (named `...sqrtf` in Ghidra; run on setup and every tick while a leg moves) sets `Joint+0xd8 = clamp(current anchor distance, m_length_min, m_length_max)` and the b2 length (`b2DistanceJoint +0xa4`) `= Joint+0xd8 * 0.05`; and the state machine writes the b2 frequency (`+0x80`). **`m_length` / `m_length_max` (31.04 game) are only the clamp bounds** (`m_length_min` unset = 0): with the leg folded the anchor distance is 13.57 game units (0.678 b2), below the bound, so the b2 length is the folded-pose distance, which is your constant 0.678. No rope (b2 type 10) joint exists on a leg: a kind-3 joint would create one (`maxLength = distance * 0.05`), none of the leg joints is kind 3.
**2. Initial pose and gear.** The folded pose is **set by code, not found by gravity**: `FUN_1401bcab0` (driven by `FUN_1401bccb0`, called from `BattleSpawner_SpawnShips`, the other ship spawners, `deployFromReserve` and `SomethingWithLevelSerias`) puts each leg part at world angle `= (Frame +0x138, or the part's own angle if the master is not a Frame) + limit + m_angle_reference` with `limit = m_angle_min (+0xfc)` if `m_cw (+0x110) == 0` else `m_angle_max (+0x100)`, sets the part state `+0x3cc = 1` (retracted), moves the body so the two pins coincide (`setXposYpos`), runs `Joint_UpdateLength` on the strut, writes its frequency 10.0, and recurses along the chain through the kind-1 joints whose node A is this leg. So at spawn **every revolute sits exactly on its folded limit** (joint angle = that limit): Fenek 0->11 at -1.5708 (cw 0, lower), 11->12 at the upper limit (cw nonzero), consistent with your rest values (min -1.5710 for 0->11, max 1.5644 for 11->12, a slop away). The pose in the seria (joint angle 0 or the design pose) is overwritten.
* **State machine** (`creatureLogic` leg case 0x14003878f..0x140038b71, part `+0x3cc`: 0 retracting, 1 retracted, 2 deploying, 3 deployed; creature aggregate `+0xb48`): target = for **retract** `m_cw == 0 ? m_angle_min : m_angle_max`, for **deploy** the opposite limit. While `|wrap(b2 joint angle - target)| >= 0.1 rad` (0x14035278c): `Joint_SetMotor(revolute, speed = +-0.5 rad/s, torque = Stats+0x104 = m_mdl_leg_force)` (+0.5 toward the upper limit, -0.5 toward the lower: retract `cw == 0` gives -0.5, deploy `cw == 0` gives +0.5; the motor is relative, torque raw 400 for LEG_02, 100 / 1600 / 3200 for the others), `Joint_UpdateLength(strut)` every tick and **strut frequency 1.0 Hz** (damping ratio unchanged 10). At arrival (|error| < 0.1): `Joint_SetMotor(revolute, 0, 0)` (motor off), and the strut frequency becomes **10.0 Hz when retracted (state 1)** or **`clamp(creature +0x15b8 / (leg force * 1000), 3.0, 10.0)` Hz when deployed (state 3)** (0x14001c7b0 is a clamp: value, low 3.0, high 10.0), and the part and creature states become 1 / 3. The strut length keeps the value of the last moving tick. A full limit-to-limit swing takes `(max - min) / 0.5` s (3.1 s for 1.5708 rad, 3.9 s for 1.9635, a little less because it stops 0.1 rad early) if the motor torque suffices.
* **What controls it.** Command `0x19a` (410, in the leg part's spasm list {27, 400, 410}; handled in `Part_HandleCommand` only for logic id 400): value < 0 toggles (state 0 or 1 -> 2 deploy, 2 or 3 -> 0 retract), value 1 -> 0 (retract), value 3 -> 2 (deploy). It is sent by `FUN_140079b20(creature, v)` to every body part in `creature +0x1330` (skipped when `creature +0xb48 == v`), whose callers include **`Input_KeyUp` key 0x1007 with v = -1 (the GEAR control, `TITLE_CTRL_GEAR`, "GEAR UP" / "GEAR DN"; gated by `doRecoil_global == 0`; the key binding is the player's)**, `aiShipDriver` (two call sites 0x140073d81 / 0x14007400f: AI ships move their gear), the spawners (initial state), `SomethingWithLevelSerias` and `memmoveMAIN` (ship set-up). The gear action therefore drives the revolute motor and the strut frequency/length (not the limits, not a swap of lengths): all leg joints change state at the same time, which is the "all joints flip from one limit to the other" in your log.
**3. Leg bodies.** Own b2 body each (slot type 282, master = global node): `MDL_LEG_02` in `parts.seria`: density 200, `m_mass` 17992.3 (game units; the b2 mass is `min(w,h) * 0.05 * density * area` as for every fixture), health 80, layer 7, `is_leg` true, logic 400, mesh a quad about 2.7 x 13.3; `MDL_LEG_01` mass 2836. Created by `Body_CreateB2Body` like every free body: linearDamping = angularDamping = 0.05, gravityScale 1.0, allowSleep, friction 0.6, restitution 0.001, no collision with the own ship (same owner id). Strength terms: `m_mdl_leg_force` 100 / 400 / 1600 / 3200 for LEG_01..04.
