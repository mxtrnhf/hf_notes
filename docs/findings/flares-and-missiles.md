## 1. Correction: Stats category 0x80 is the truss / hardpoint, not a flare [V + game]
The Stats records with `m_category = 128` (0x80) in `Libraries/OL.seria` are exactly the structural parts `MDL_FERMA*` and `MDL_HARD*` (19 records: 1x1, 2x1, 2x2, 4x4 variants). No flare, decoy or missile record has the bit. So the earlier notes' phrase "flare/decoy (category 0x80)" is wrong in three places, all now corrected:
* `b2CListener_PreSolve` `0x140284730`: an explosive projectile (`+0x1c0 & 0xd == 0xd`, explosive `+0x2dc > 0`) touching a **truss / hardpoint** part gets, once per (projectile, part) pair, with probability 0.9 a small blast (scale `2 sqrt(E) / 10`, radius `sqrt(E)`) and the contact is disabled so the projectile passes through. It is a "thin structure" rule, not a flare rule.
* `FUN_140029b60` (the blast routine): parts of category 0x80 do not reduce the penetration strength (trusses do not stop a penetrating shell).
* `Creature_AccumulatePartStats` tests the same bit.

## 2. The flare body (`FireFlareLauncher` `0x14002eed0`) [V]
* Gate: launcher cooldown `+0x848 == 0`, `+0x80c` and `+0x818` non-zero, loaded `+0x860 >= 1`, rate timer `+0x86c == 0`. Then `loaded -= 1` and the rate timer is set to `1 / (rpm / 60)` (`FUN_1400490a0`; part data `m_weapon_rate = 400`, magazine 30, `m_weapon_load_time 99999`).
* The flare is a `CreateShell?` body: a **triangle (n = 3), size 0.5, density 1.0** (mass about 0.03), `ttl +0x2c0 = 5.0 s`, stage `+0x8d8 = 5`, drag `+0x1dc = 0.0007`, logic `+0x3c4 = 0x44c` (1100), and **collision mask `+0x1f0 = 0`: it collides with nothing** (not with ships, shells, missiles or ground; `ShouldCollide` rule 1 needs a common bit).
* Velocity: first set to the ship's root velocity (`Body_SetLinearVelocity` with root `+0x130/+0x134`), then an impulse `rand(0.9, 1.5) * 400 * mass` along the launcher's world direction rotated by `rand(-0.2, +0.2)` rad. So a flare leaves at 360 to 600 units/s relative to the ship and decelerates with the 0.0007 quadratic drag plus the standard 0.05 damping. Spawn point = the launcher's world position. Visuals: `smoke_FIRE.psi` (smoke_09), `rocket_glow.psi` (rocket_glow_03), `fire_LRE.psi`.
* **No code anywhere compares a body's logic id with 1100 (0x44c)** (program-wide search for the immediate in compares and subtractions: only the store in `FireFlareLauncher` and an unrelated stack constant). So the logic id does not make seekers target a flare, and the flare body has no per-frame logic branch that I could find. **How a missile seeker is lured by a flare is not decoded**; the likely place is the guided-missile block of `creatureLogic` (see section 4), which I could not read in full (the decompiler times out on it).

## 3. Missile launch and ejection [V]
* Launch chain as in combat-missile-launch.md: `LaunchZenithAtOwnerTarget` `0x14002ff60` sets the target link at `launcher +0x490` (pointer `+0x498`) and the owner link at `+0x4a8` (pointer `+0x4b0`), `+0x3c8 = 1`. The tactical missile is a ship part (`MDL_MISSILE_01`, category 0x4000, explosive 300, penetration 30) that `creatureLogic` detaches after a countdown (call `0x140037809`).
* Ejection code (`creatureLogic` `0x140035e3b..0x14003601f`): the part is placed at its world position with its master's offset, **given the ship's velocity** (`Body_SetLinearVelocity(part, root +0x130, +0x134)`), collision mask `+0x1f0 = 7`, flags `|= 0x25`; a random impulse `rand(1, 2) * 30 * mass` along the part axis (direction jittered by `rand(-0.01, 0.01)` rad) and a small random spin (`rand(-0.05, 0.05)` offset impulse); then the state counter `+0x3cc` is incremented and a timer `+0x3d0` set (`rand(0, 3)` or `rand(1, 3)`).
* Missile state machine: `+0x3cc` (state), `+0x3d0` (timer), `+0x3d4` (parameter, 1.5 for rockets), `+0x3d8` (heading reference), `+0x3dc`, `+0x3e4` (direction sign); the proximity / closing block starts at `0x140036780` and ends in the death method `Body_DieExplode` `0x140023ac0` after dividing the explosive `+0x2dc` by 5 (minimum 10) and spawning the blast effect `FUN_140032fb0`.
* Contact rule for missiles vs everything: collision mask 7 and flags `0x25`; `Projectile_DetonateOnImpulse` (needs `+0x38c >= 0`, set by the arming code in state 1: `+0x38c = mass * [0x140354828]`) and the zero-impulse proximity case in `Physics_ProcessContactRecord` (state `+0x3cc == 2`, owner matches) detonate them.

## 4. What is still open (and why)
* The seeker / guidance law (how the heading is steered toward the target link, or toward a flare), the proximity fuze radius, the arming time: all inside `creatureLogic` `0x140033b90` (about 7 KB of the guided-missile blocks between `0x140035e3b` and `0x140036ca0`, helper vector functions `0x140018910` / `0x140018930` / `0x140019480`). The Ghidra decompiler times out on this function; a way forward is to disassemble the blocks in chunks with constants resolved (the way the ejection block above was read) or to log the missile heading each frame next to the target and flare positions.
* Empirical cheapest route: the probe's `BLAST` lines already show the missile explosive; add a per-frame log of `+0x3cc`, `+0x3d0`, heading `+0x138`, velocity and the target link position for bodies with logic 130 / 160 during a flare drop.
