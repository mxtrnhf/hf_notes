# Battle telemetry for AI research (`hf_ally` v0.12.3 / v0.12.4)

Status (2026-10-18): **v0.12.3 ran in game (two captures); v0.12.4 (parts, bodies, many new columns) is built, installed and has NEVER run: everything specific to it is [code] / untested until its first capture.** Source: `hf_ally/src/telemetry.rs` (local repo, commit `7fcf279`, no remote). Tags: legend in `../../README.md`.
Purpose: the harness of "Where to take the AI" stage 3 in [battle-ally.md](battle-ally.md): record how the player flies and what the enemy AI does, so tactics can later be chosen from data. Plan order: telemetry, then a tactic state machine on the steering-waypoint hook (`0x140064a8d`, see [ai-flares.md](ai-flares.md)), then a player-model "director" that picks tactics. Read-only: no game memory is written and no game function is called; every pointer is read through the page-checked `diag::rd`.

## How to run it
* Config `Modloader/config/ally.json`: `"telemetry": true`; `"spawn_ally": false` gives a solo capture (the battle-manager hook is installed when `spawn_ally` OR `telemetry` is on). F9 drops an optional marker row; it is not needed.
* Output in `Modloader/logs/`, one session per game run segment (see "Session" below): `hf_ally_telemetry_<unix>.csv`, `hf_ally_parts_<unix>.csv`, `hf_ally_bodies_<unix>.csv`. Written unbuffered; a crash loses nothing. Send all three plus the newest `Highfleet_*.log` and `hf_ally_megalog_*.log`.
* `python3 hf_ally/tools/telemetry_summary.py hf_ally_telemetry_<unix>.csv` : speed, range bands to the nearest armed enemy, buttons/boost time, flares, rounds, Zenith drops, markers; warns when a row's field count differs from the header.
* `python3 hf_ally/tools/telemetry_damage.py hf_ally_parts_<unix>.csv` : per ship the parts seen, the strings found in the ship object, health lost per second (written for v0.12.4, untested on real data).

## Files and columns
**`hf_ally_telemetry_*.csv`**, about 10 rows per game second per live ship. `P` = the ship the player flies (chosen as live, role `+0xd70 == 1`, AI flag `+0xbd4 == 0`), `E` = every other live creature (friend, foe, neutral), `M` = F9 marker. Columns (v0.12.4): `t` game clock, `kind`, `id` (P is 0; others numbered by first sight), `side` (`+0xad4`, negative = enemy), `state` (`+0xbdc`), `x,y` (`+0x1840/+0x1844`, centre of mass), `target_id` (-1 unknown, 0 = the player), `gun_*` / `zen_*` / `fl_*` (count, loaded sum, reserve sum of the weapon list `+0x1360`, Zenith list `+0x13d8`, flare list `+0x1408`; flares: loaded and reserve semantics unchecked), `parts_n, parts_alive, hp_sum, hp_max0` (from the part list, below), `fuel, fuel_cap` (`+0x1638`, f64), `crew, crew_cap` (`+0x17ec`), `aggr` (`+0xbc4`), `retarget` (`+0xb28`), `wp_x, wp_y` (the AI waypoint `+0xbf0/+0xbf4`), `launch_cd` (`+0xd60`), `mode` (`+0xb48`), `role` (`+0xd70`), `ai` (`+0xbd4`), `reach1, reach2` (`+0x1838/+0x183c`), `rp_*` (first part-list entry: position, velocity, angle), `cr_*` (creature `+0x130/+0x134/+0x138` raw), `f0..f4` (control bytes `+0xbbc..+0xbc0`), `ammo_flags` (hex of `+0xc74..+0xc7e`). Player only: `boost` (`+0xba8`), `lmb, rmb` (`GetAsyncKeyState`), `mx, my` (HGE `+0x9fc/+0xa00`), `amx, amy` (their sum since the last sample), `zoom` (`0x1403c11cc`), `vc0..vc7` (8 floats at `0x1403c0dc0`, candidate virtual cursor from probe run 1), `wave_t` (`0x147fc7020`), `ctl` (hex of `+0xba0..+0xbe0`). v0.12.3 had only the first 17 columns plus `f0..f4`, `boost`, `lmb, rmb`, `mx, my`, `amx, amy`, `zoom`.
**`hf_ally_parts_*.csv`** (v0.12.4): `S` a part seen (with `oid`, e.g. `MDL_CANNON_30_6`, stats index, state, health, max health, local x,y), `H` health or state changed (the damage log), `L` part left the ship's list, `N` one per ship: every MSVC `std::string` found in the creature object as `offset:text|...` (the design name is expected among them; offset unknown). Columns `t,kind,ship,part,oid,stats,state,hp,hp_max,lx,ly`.
**`hf_ally_bodies_*.csv`** (v0.12.4): `C` per sample, counts of flying bodies by logic id (`100` shell, `130` rocket, `135` harpoon, `140` laser guided, `160` proximity, `1100` flare, see [../structures.md](../structures.md)); `B` for each body with a target link (missiles, torpedoes; cap 80 per sample): logic, stats index, position `+0x128/+0x12c`, velocity `+0x130/+0x134`, health, time to live `+0x2c0`, target ship id.

## Addresses used (1.163) [code]
* **Whole-ship part list:** Creature `+0x1330` (begin) / `+0x1338` (end), 0x18-byte entries, Node at `+8`; the loop in `CalculateStats` (`0x14007fcf0`) walks it and calls `0x140071380` per part with class code `0xf`.
* **Part health:** Body `+0x2c8` current, `+0x2cc` max; `calcDMGPercentage` (`0x140048410`) is exactly `+0x2c8 / +0x2cc`. Part state `+0x48` (0 = dead or dropped, from [../structures.md](../structures.md)). `hp_sum` / `hp_max0` are sums of these per-part numbers, NOT a game "ship health" (the game has none in one field).
* **Per-category lists** in the creature, same stride, found in `0x140071380`: `+0x1348` power, `+0x1360` weapons, `+0x1378` fuel tanks, `+0x1390` engines (thrust), `+0x13a8` / `+0x13c0` gun groups, `+0x13d8` Zenith, `+0x13f0` second launch list, `+0x1408` flares, `+0x1438` bombs, `+0x1480` crew, `+0x1498` sensors, `+0x14f8` legs.
* **Flying bodies:** array of `Body*` at `0x143a33c90`, count (u32) at `0x143a51150` (the arrays `FUN_14002f480` and the QoL `ai_flares` threat scan walk).

## Known defects and unknowns (do these first)
1. **Session never closes between battles** (the roster is not empty between them). In v0.12.4 ships and parts are keyed by pointer: a ship at a reused address inherits an old id, gets no `S` / `N` rows and corrupts `hp_max0`. Fix: close or reset the session when the player row has been absent for more than 1 s.
2. `telemetry_summary.py` treats a file as one battle: its max speed (28544) is a position jump between battles, rounds are over-counted when guns reload (the loaded+reserve sum dips), and `zen_n` drops cannot tell "launched" from "shot off".
3. **Cost under Proton:** `diag::rd` calls `VirtualQuery` on every read; parts and bodies make thousands of calls per sample. Not measured.
4. Unknown: the ship-name offset (the `N` row should reveal it), the camera / world aim direction (the `vc*` floats and the mouse sums are the candidates), the meaning of `rp_*` / `cr_*` (creature `+0x130..` may not be the ship's physics; compare with position differences), what `f1` is, whether flare `loaded`/`reserve` use the same fields as guns.
