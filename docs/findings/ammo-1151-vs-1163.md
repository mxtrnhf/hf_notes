# The ammo table: how it is built, and what changed between 1.151 and 1.163

Status: **read from both decompilations; the diff below was produced by a script, not by eye.** Not tested in game. Tags as in `../../README.md`: **[game]** verified on the real game files · **[code]** read from the decompilation · **[guess]** inferred.
Addresses are 1.163 (image base `0x140000000`, the unpacked exe) unless marked 1.151. Origin: roadmap items about HP, TTL and damage of shells and the "damage changes" in the version scope.

## Where the table is
* The ammo table is **built in code**, not in `OL.seria`: `DefineAmmos` (1.163 `0x140256f10`-`0x14025afc4`; 1.151 `0x1402356d0`) fills the global `AmmoDefList` (1.163 `AMMO_LIST_BEGIN` at `0x143a13be0`, end pointer `AMMO_LIST_END`). Found in 1.163 through the global's references (168), not by name.
* `FireShell` (1.163 `0x1400300d0`) dispatches on the entry's `index`; `FireGun` passes the gun's ammo slot. Entry stride: **1.151 `0x168`, 1.163 `0x188`**. (An earlier version of the working notes said `0x188` for 1.151 too; that was wrong.)
* Every derived entry (`_INC`, `_AP`, `_PROXY`, `_LG`) copies its base entry, including `index`, then changes a few fields, so all variants of one calibre share one `FireShell` case.
* `OL.seria` links to the table through `m_weapon_caliber`, which **equals the ammo `index`** [game]: `MDL_CANNON_30_6` 5, `MDL_CANNON_57_2` 10, `MDL_CANNON_100_2` 15, `MDL_CANNON_130` / `_LOW` 20, `MDL_CANNON_180` / `_180_2` 25, **`MDL_CANNON_305_2` also 25** (it fires 180mm shells, so `ITEM_AMMO_305MM`, index 40, and `ITEM_AMMO_203MM`, index 30, have no vanilla gun), `MDL_RSZO_220` 52, `MDL_TORPEDO_300` 54, `MDL_CANNON_HARPOON` 90, `MDL_KAZ` 100.
  Inside the table, `caliber` is *not* a size: `BulletImpact__` stores it as the projectile's **logic id** (100 plain shell, 130 rocket, 140 laser guided, 160 proximity; 1.163 adds 132 for the 300mm rocket and 135 for the harpoon).

## The big change: `ttl`, shell lifetime per ammo type [code]
1.151's `BulletImpact__` (`0x140050300`) set the shell's `timeToLive` / `desowningTime` to a literal **10.0**, with 1.0 if `penetrativePower != 0` (AP), 3.0 for index 10 and 2.0 for index 5. 1.163's (`0x140052a80`) reads **`ammo->ttl`** (1.0 if `penetrative_power != 0`, as before). Values in `DefineAmmos`:

| Shell | 1.151 lifetime (s) | 1.163 `ttl` (s) |
|---|---|---|
| 37mm | 2.0 | 2.0 |
| 57mm (and the new `ITEM_AMMO_57MM_TANK`) | 3.0 | 3.0 |
| 100mm | 10.0 | **4.0** |
| 130mm | 10.0 | **7.0** |
| 180mm | 10.0 | **30.0** |
| 203mm, 305mm | 10.0 | 10.0 (default) |
| AP variants (100 / 130 / 180) | 1.0 | 1.0 |

Shell range is lifetime times muzzle speed (`speed` 700 for the base shells), so a 100mm shell now lives 4 s and a 180mm shell 30 s. This is the first hard evidence of a gameplay difference between the versions beyond the speed curve; whether it is felt in play is untested [guess]. It is a data constant per ammo type, so it is patchable at the stores in `DefineAmmos`. It is **not** the roadmap's "TTL for cluster munitions and mine bomblets" (a separate mechanism: the sixth argument of `FUN_140032fb0`, the bomblet spawner).

## Every other value change (scripted diff of the 22 changed entries) [code]
Method: the 1.163 `DefineAmmos` decompile was parsed by script into per-entry stores (offset, value); the 1.151 stores were transcribed from its decompile; both were compared field by field for every entry present in both. Strings (names, sounds, sprites) were not compared. Fields set by the base entry are compared on the base; derived entries compare their overrides.

| Entry | Field | 1.151 | 1.163 |
|---|---|---|---|
| `ITEM_AMMO_220MM` | `explosive_power` | 90 | **180** |
| `ITEM_AMMO_300MM` | `explosive_power` | 90 | **500** |
| `ITEM_AMMO_300MM` | `caliber` (logic id) | 130 | **132** |
| every `_INC` entry (37, 57, 100, 130, 180, 220, 300mm) | `incendiary_power` | 1000 | **300** |
| `ITEM_AMMO_130MM_LG`, `ITEM_AMMO_180MM_LG` | `explosive_power` multiplier on the base | x4 | **x1.5** |
| `ITEM_FAB250` | shop price / aircraft strength | 100 / 5 | **200 / 6** |
| `ITEM_K13` (air-to-air) | shop price | 300 | **400** |
| `ITEM_GUN37` | `fire_delay` (`gun_rate_time`) / `gun_max_load` | 0.1 / 10 | **0.05 / 20** |
| base shells 37..180mm, AP variants (100/130/180) | `ttl` | none | see above |

Unchanged (confirmed by the same diff): the base cannon `explosive_power` / `speed` / `bullet_height`, the AP penetrations 16 / 20 / 34 and `apDrag` (0.0007), the rocket speeds and pod stats (`ITEM_NAR122`, `ITEM_NAR340`), `ITEM_GUN57`, `FAB100`, `FAB500`, and the shop price / rarity / amount of every other entry.
**New in 1.163:** `ITEM_HARPOON` (`index` 90, `caliber` 135, `speed` 700, `explosive_power` 0), `ITEM_KAZ_AMMO` (`index` 100; no `FireShell` case, the burst is `FUN_14002f480`), `ITEM_AMMO_57MM_TANK` (`index` 10, `caliber` 0 = no projectile logic).

## Index map (the `FireShell` key) and what is not in the table
5 37mm · 10 57mm · 15 100mm · 20 130mm · 25 180mm · 30 203mm · 40 305mm · 51 `NAR122` · 52 220mm rocket · 54 300mm rocket · 55 `NAR340` · 90 harpoon · 100 KAZ. `FireShell` also has cases 60 (`0x3c`) and 70 (`0x46`) (canisters of 3 and 6 pellets) and 80 (`0x50`, EMP) with **no `DefineAmmos` entry in either version**; they come from other code (not read).
**1.151 vs 1.163 `FireShell`:** 1.163 adds cases 54 (`0x36`, the 300mm rocket, which had no case in 1.151 and therefore fell to the default: only the muzzle flash [code]; "so it did nothing in play" is a guess) and 90 (`0x5a`, the harpoon). 1.151's difficulty-scaled "special behaviour" roll (`0.5` / `0.75`) is gone from 1.163, replaced by a launch timer from `FUN_1401af7b0(n)` with `n` = 1, 3, 5, 6 or 8.
**All plain cannon shells have 1 HP** (an argument of `BulletImpact__` in `FireShell`), the number behind the roadmap item "calibers above 30 mm should not destroy missiles / rockets / shells in one shot".
