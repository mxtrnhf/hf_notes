# Battle terrain: how the ground is built and queried (v1.163), ghidra-miner, 2026-10-21

Tags: **[V]** read in the 1.163 program; **[game]** read in the game's data files; **[guess]**. Mechanism, scene map, zero level and noise amplitude are in sections 3 and 7 (section 7 supersedes the "0 or 1" hill claim and the open noise question below); what is still unread is listed in section 6.

## 1. There is no terrain in the level file [game]
`Data/Levels/Combat.seria` (also `CombatSkirmish`, `CombatSkirmishPVP`, `Combat_test`) is an empty shell: `LVL_HIGH (1500, 2000)`, `LVL_LOW (-1500, -2000)`, `LVL_WIND_FORCE 3`, `LVL_BACKGROUND background_mid_01`, two empty root nodes, and **no `LVL_LANDSCAPE_*` keys**. Only `City.seria` sets them (`SEED 1260`, `SIZE 7000`, `L1 400`, `L2 60`, `HILL 1`, `ZERO 0`, `CITY_SIZE 800`). The arena box is the whole level size; other levels: Bombers 6000 x 6500, CraftsVsCrafts 5500 x 7000, CraftsVsMissile 4000 x 6500.
So the ground is **generated by code at scene start** from level properties that the scene state machine (`SomethingWithLevelSerias`) writes into globals.

## 2. Parameters (level property -> global) [V, `InitializeLevelProperties` 0x1402da000]
| Key | Global | Type | Meaning (as used) |
|---|---|---|---|
| `LVL_LANDSCAPE_SEED` | `0x147fc6f84` | int | noise seed |
| `LVL_LANDSCAPE_SIZE` | `0x1403c2b6c` | float | ground width, centred on x = 0 (points from `-size/2` to `+size/2`) |
| `LVL_LANDSCAPE_L1` | `0x1403c2b70` | float | passed to the noise generator `FUN_140283910(obj, 10, 3.0, L1)` |
| `LVL_LANDSCAPE_HILL` | `0x147fc6fa0` | float | amplitude factor of the cosine hill term; **random 0..1 in the combat scenes** (section 7) |
| `LVL_LANDSCAPE_ZERO` | `0x1403c2b74` | float | ground level offset (200.0 in the shared setup at `0x1402c38e5`) |
| `LVL_LANDSCAPE_CITY_SIZE` | `0x147fc6fa4` | float | flat city plateau size (generator uses `2 * city_size`) |
| `LVL_LANDSCAPE_CLOUDS` | `0x147fc6fac` | float | cloud layer parameter |
The shared setup block (e.g. `0x1402c3720..0x1402c3958`) sets `L1 = rand(200, 800)`, `seed = rand(0, 9999)` **or the location object's `+0x2a8`** (object at `0x143a11940`), `ZERO = 200`, `city_size = location+0x248`, then calls `generateCityLandscape(flag, mode)`. There are 15 call sites (the 11 in `SomethingWithLevelSerias` plus 4 more in scene code); the same code serves landing/city scenes.

## 3. The height function (`generateCityLandscape` 0x1402eeb90, 20 KB) [V]
Builds a polyline `P[i] = (x_i, y_i)`, global array at `0x14801fd30` (x, y float pairs), count at `0x14800ee1c` (max about 999 points):
* `x_0 = -size/2`, `y_0 = 0`; then `x` steps by **150** up to `+size/2`.
* `y = -(cos(x * 0.0020943952 + 0.4) + 1) * 0.5 * 400 * env * hill + noise(seed, (x + size/2)/size)` with `env = clamp(1 - (x/1500)^2, 0, 1)` (period 3000, hills only inside |x| < 1500, i.e. under the arena; amplitude up to 400 units times `hill`).
* Smoothing pass(es): each point is clamped to within **+-50** of its neighbour (max slope 50/150 = 1/3, 18 deg).
* The sign (y = -height) matches the render code (`screenY = H/2 - h - 100`); the game's y axis points down, and the logged flights put the ground at y +160..+420 (older estimate in `runs/ai-underside.md`).
The noise term is resolved in section 7 (10-octave Perlin sum, amplitude `L1`).

## 4. Query [V]
`FUN_1402ee0c0(out Vec2*, in Vec2* pos, int* hint)` = **ground height at x**: walks the polyline from index `*hint` (0 if null) to the first point with `x >= pos.x`, linearly interpolates, writes `(x, y_ground)`; clamps to the first/last point outside the range, stores the index back to `*hint`. Callers (not read, names are Ghidra's): `FUN_140023ac0`, `FUN_1401c7270`, `FUN_14022ad00` (the debris/particle effect), `FUN_1402d45c0`, `SomethingWithLevelSerias`, `UpdateZoom`, `afterBattleStars??`, `battleSfx?`, `displayRepairMerchantCity`, `handleLandingGUI?`, `renderDocksProcedurally?`, `rep_14002ca30_MakeGlobal?`, `0x1402d2d00`, `0x1402d3150`, `0x1403050a0`. `FUN_1402fd580` reads the same array for the parallax/render shift. **`AiShipTick` and `AiShip_SteerController` do not call it** (the caller list above has no AI function).

## 5. Physical ground and collision [V, partly]
After the polyline the generator copies prototype bodies (`CopyObject` from the preloaded libraries `Objects/Land` = `lnd_close_01..06` and `Objects/Rock` = `lnd_rock_01..06`, loaded in `PreLoadLibraries`; all are static polygon Bodies, `m_density 0`, `m_health 1e10`) and places one **`lnd_brick`** body per ground segment (midpoint, rotated to the segment slope), sets `Body+0x1f0 = 0x1f` (collision-layer mask), stage `+0x8d8 = 0x2a`, `+0x2d0 = 1` style flags, and rectangle fixtures from the body's bbox (`+0x21c`, `+0x218`). Decorative `lnd_rock` bodies (stage 0x29) are placed by the editor drag tool (`memcmp_editor` calls `0x1400c0560`), not by combat.
Collision: Box2D's own filter never blocks (category 1, mask 0xFFFF); the decision is `b2CFilter::ShouldCollide` `0x1402858c0` rule 1: collide only if `(A+0x1f0 & B+0x1f0) != 0` ([box2d-physics-setup.md](box2d-physics-setup.md) section 5). The brick mask is `0x1f`; I did **not** read the ship parts' `+0x1f0`. That ships do collide is shown by landed enemies (legs on the ground, `runs/ai-intrepid-benchmark.md`) and by the existing leg rule in [landing-legs.md](landing-legs.md). Ground contact damage goes through the normal contact path ([contact-damage-and-fire.md](contact-damage-and-fire.md)); the ground cannot be damaged (health 1e10, invulnerable flag).

## 7. Update 2026-10-21 (later): scene map, zero level, noise [V]
**Noise** (`0x140283c30`, Ghidra name `...srand`; object set up by `FUN_140283910(obj, 10, 3.0, L1)`): a standard 2-D gradient (Perlin) noise summed over **10 octaves**; octave `k` has amplitude `L1 * 0.5^k` and doubled frequency, base frequency 3.0 over the normalised position `t = (x + size/2) / size`. So `L1` (200..800 in combat) is the noise amplitude: expect typical excursions of a few tenths of `L1` (60..400 units) and extremes up to about `L1`. The finest octaves are finer than the 150-unit sampling and are then flattened by the +-50 smoothing.

**Full pipeline per point** (all in `generateCityLandscape`):
1. `y = -(cos(x * 2pi/3000 + 0.4) + 1) * 200 * env(x) * HILL + noise(x)`, `env = clamp(1 - (x/1500)^2, 0, 1)`.
2. Neighbour clamp +-50.
3. `y += rand(-20, +20)` (`HGE+0x110`, constants `0x14037270c` = -20, `0x140352820` = 20).
4. `y -= y(x = 0)` (interpolated), so the ground is exactly 0 at x = 0.
5. `y *= min(|x| / 600, 1)`: a **flat plateau around x = 0** (the landing/city spot), full relief beyond |x| = 600.
6. `y += ZERO` (all points).
The physical `lnd_brick` row is built from this polyline plus a 6.43 offset; its y is world y (+y down).
**So the ground is `ZERO` (200 in nearly all scenes) at x = 0 and deviates from 200 by the noise and hill terms; negative deviations are hills (up), positive are valleys.** Bounds: hill term is at most 400 * HILL above the base (and zero for |x| > 1500); noise is roughly +-`L1` at the extreme. Worst case (L1 = 800, HILL = 1) the ground top near the arena edges can reach about y = -600 to -800; a typical battle (L1 about 500, HILL 0.5) has hills of 100-250 units over a base of 200, i.e. ground tops mostly between y = +50 and +350. A ship at y < -800 is very unlikely to be near the ground; one at y = -166 can be in a bad case only if the local noise is strongly negative.
