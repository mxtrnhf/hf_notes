# How an explosive body (plain cannon shell, flak target) is detonated (v1.163), ghidra-miner, 2026-10-21

Tags: **[V]** read in the 1.163 program, **[log]** measured on the D/H probe rows of `sim_runs26` (64 plain-shell chains, 4 flights). `D` = `Body_DieExplode 0x140023ac0` (vtable +0x200) entry, `H` = set-health slot `0x140051de0` (vtable +0x208) entry; caller RVAs are return addresses minus the image base.

| D caller RVA | Function | What it is | Condition |
|---|---|---|---|
| `0x1d32c` | `Projectile_DetonateOnImpulse` `0x14001d1e0` | **contact detonation** (all 59 plain-shell chains with an impact) | see below |
| `0x2fb21` | `FUN_14002f480` (call at `0x14002fb1b`) | **anti-projectile gun** (flak "strides" gun): detonates incoming explosive bodies in its cone | see below |
| `0x51c1e` | `Body_ApplyDamage` `0x1400519d0` | death by hp (hp <= 0 after damage: missiles, fuel, ammo crates; 4 plain-shell rows with impulse 0) | hp reaches 0 |
| `0x360fa` | creatureLogic | missile logic (not shells) | - |

## 1. Contact detonation [V + log]
In `Physics_ProcessContactRecord` `0x1402849a0` (one Box2D contact per call): `I = rec[+0x40] / 0.05^4` (four divides by `0.05` at `0x140284c67..0x140284c82`, = 160000 x the contact's max normal impulse; the same `I` as in the damage formula and the tear-off test). Contact damage is applied to both bodies first (`vtable +0x210 = Body_ApplyDamage`, `0.8 * rec[+0x40]` = 5e-6 * I; this is the `H` row: the logged hp drop 1.0 to 0.94..0.97 is exactly `0.8 * I/160000`). Then **for each of the two bodies** (`0x1402857c9..0x140285814` for A, `0x140285826..0x140285870` for B):
```
if body.IsActive(vtable +0x78)  and  0.0 <= body[+0x38c] < I :   Projectile_DetonateOnImpulse(body, other, ...)
```
(`XMM10 = 0.0` is set by `XORPS` at `0x1402849f4`; `COMISS` skips if `+0x38c < 0` or `I <= +0x38c`.) `Projectile_DetonateOnImpulse` then (only returns early for an `MDL_FIGHTER_01` owner special case): `if body[+0x2dc] (explosive) != 0: body.vtable +0x200(body)` = `Body_DieExplode` (the blast). Logic id `0x87` (harpoon) additionally sticks. So the exact rule is **explosive != 0 and 0 <= body+0x38c < I**, evaluated for every contact record the handler processes (it skips several mode and creature cases, see the plate comment of `Physics_ProcessContactRecord`).
* `+0x38c` ("collisionSensor"): the `Body` constructor (`setCertainBodyFloatVals` `0x140049570`) writes **-1.0**, which would never trigger. Writers I found: fragments `FUN_14001c890` (= body mass `+0x1d8`), cluster bomblets (`Projectile_ExplodeAndCluster`), armed missiles (`creatureLogic` state 1 of `+0x3cc`: `+0x38c = mass * 25.0`, after a 0.05 s arming delay), `Body_DieExplode` itself (`+0x2dc = 20.0`, `+0x38c = mass`), `bodySecondaryInit` (parsed from a `m_collision_sensor` property of object data: used by `Objects/Land/lnd_close_*`, towns), `copyOverBody` (copy). **I found no writer for plain cannon shells** (`CreateShell_` does not touch it). Yet [log] **every one of the 64 plain-shell contacts that took contact damage was detonated in the same step by this path**: 27 explosive-14 shells with impulse 3586 / 9122 / 11909 (min / median / max) and 33 explosive-20 shells with 8021 / 15405 / 22962, hp 0.91 to 0.97 at the call, ttl 3.7 to 6.5 s left; none survived a contact. So for plain shells the effective threshold is below 3586 (a threshold of 0 is consistent); the arming writer is unresolved [open]. My earlier statement that cannon shells never take this path (guns-aim-reload-fire.md sections 7/9, blast-and-penetration.md) was wrong and is corrected.
* **Model for the sim**: a plain shell explodes at the first processed contact whose normal impulse is not tiny (all observed impulses were >= 3586 in these units, i.e. raw b2 impulse >= 0.022); contact damage is irrelevant to the trigger (hp stays about 0.95).
* Zero-impulse case (`I == 0` exactly): `0x140284d76/0x140284daa` call the same function for missiles whose state `+0x3cc == 2` and whose owner link matches (proximity fuze), not for shells.

## 2. Anti-projectile gun [V + log]
`FUN_14002f480` (called per creature from `CreatureUpdate`) runs for a weapon part that is ready (`+0x848 == 0`, `+0x80c != 0`, `+0x818 != 0`, ammo count `+0x870 >= 1`, cooldown `+0x86c == 0`). It scans all active bodies for a threat: `+0x3e0 != 0`, `penetration (+0x2e0) + explosive (+0x2dc) >= Stats(AMMO_100MM)+0x160`, not owned by this creature, distance <= 60 (`magnitudeCreatureBodyVector`), Stats flags `+0xb0` not in {0x4000, 0x8000000, 0x200000} and bit 10 clear, bearing within +-45 deg (`0.7853982`) of the gun direction and heading toward the gun (angle of the velocity > 90 deg). If one is found the gun fires (cooldown from Stats `+0x150`), and **every body within 120 units and within +-45 deg of the gun direction that has explosive != 0 (flags `& 0x405 != 0x405`, same Stats exclusions) is detonated with `vtable +0x200`** (`0x14002fb1b`); that is the `0x2fb21` rows (intact shells, hp 1, impulse 0). It then spawns "strides" particle effects. Player guns are not involved (it is a creature weapon type).
