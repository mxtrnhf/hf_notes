## 1. Contact detonation [V + log]
In `Physics_ProcessContactRecord` `0x1402849a0` (one Box2D contact per call): `I = rec[+0x40] / 0.05^4` (four divides by `0.05` at `0x140284c67..0x140284c82`, = 160000 x the contact's max normal impulse; the same `I` as in the damage formula and the tear-off test). Contact damage is applied to both bodies first (`vtable +0x210 = Body_ApplyDamage`, `0.8 * rec[+0x40]` = 5e-6 * I; this is the `H` row: the logged hp drop 1.0 to 0.94..0.97 is exactly `0.8 * I/160000`). Then **for each of the two bodies** (`0x1402857c9..0x140285814` for A, `0x140285826..0x140285870` for B):
```
if body.IsActive(vtable +0x78)  and  0.0 <= body[+0x38c] < I :   Projectile_DetonateOnImpulse(body, other, ...)
```
(`XMM10 = 0.0` is set by `XORPS` at `0x1402849f4`; `COMISS` skips if `+0x38c < 0` or `I <= +0x38c`.) `Projectile_DetonateOnImpulse` then (only returns early for an `MDL_FIGHTER_01` owner special case): `if body[+0x2dc] (explosive) != 0: body.vtable +0x200(body)` = `Body_DieExplode` (the blast). Logic id `0x87` (harpoon) additionally sticks. So the exact rule is **explosive != 0 and 0 <= body+0x38c < I**, evaluated for every contact record the handler processes (it skips several mode and creature cases, see the plate comment of `Physics_ProcessContactRecord`).
* **RESOLVED (later 2026-10-21): the arming is the per-tick logic of logic id 100 (plain shell), `creatureLogic` block at `0x140033d47`** (state `+0x3cc`, 0 -> 1 -> 2; runs only while the byte `0x143a11909` is 0):
  * state 0 (first tick): `+0x3d0 = 20.0 / |v|` (`|v|` = magnitude of the shell velocity `+0x130/+0x134`, constant `20.0` at `0x140352820`), state := 1. That is an arming distance of 20 game units (one b2 metre) travelled at the launch speed.
  * state 1: if `+0x3d0 >= 0` then `+0x3d0 -= dt` (global `0x1403c126c`); once it is negative: **`+0x38c = mass(+0x1d8) * 25.0`** (constant `0x140354828`), state := 2. Armed.
  * every tick (all states): `Body_SetAngularVelocity(0)` (`0x140051760`: the shell does not spin) and, if the test `0x14001dab0(body, 0x205)` passes and the angle `+0x138 != 0`, `0x140051850` re-aligns the shell to its velocity.
  * Before arming `+0x38c = -1` (the `Body` constructor), so a hit in the first ~20 units of flight (about 20/speed seconds, a few ticks) does NOT detonate and only does the tiny contact damage.
  * **Threshold = 25 x shell game mass** (masses in guns-aim-reload-fire.md section 9: 37 mm 0.95, 57 mm 3.6, 100 mm 15.9, 130 mm 31.7, 180/305 mm 85.6, 203 mm 114): 24, 90, 397, 793, 2140, 2850. Detonation needs `I = 160000 * raw impulse > 25 * m`, i.e. a normal-velocity change of more than about 25 game units/s (1.25 b2 m/s) for a hit on a heavy body. Check [log]: the probe's contact impulses (explosive 14 = 100 mm: 3586 / 9122 / 11909; explosive 20 = 130 mm: 8021 / 15405 / 22962) are 10 to 30 times the threshold (397 / 793), consistent with 64 of 64 contacts detonating; only grazing contacts (normal-velocity change under 25 u/s) would survive.
  * Other values of this machine in the same function (logic id -> block): 110 `0x140033ce8` = timed fuse (state 0: `+0x3d0 = +0x3d4`, state 1: `Body_DieExplode` when the timer is spent); 120 `0x140033c5a` = delayed warhead (state 1: `+0x38c = 10000.0`, `+0x2dc = +0x3d8`, logic id := 0); 135 `0x140035553` = missile arming (`+0x38c = mass * 25`, 0.05 s delay `+0x3d0`, state 2); full table in creature-logic-id-map.md.
  * Other `+0x38c` writers: fragments `FUN_14001c890` (= mass), cluster bomblets (`Projectile_ExplodeAndCluster`), `Body_DieExplode` (`+0x2dc = 20.0`, `+0x38c = mass`), `bodySecondaryInit` (property `m_collision_sensor` of land/town objects), `copyOverBody`.
* **Model for the sim**: a plain shell explodes at the first processed contact after it has flown about 20 game units (`20/|v|` s), when `160000 * raw impulse > 25 * mass`; contact damage is irrelevant to the trigger (hp stays about 0.95).
* Zero-impulse case (`I == 0` exactly): `0x140284d76/0x140284daa` call the same function for missiles whose state `+0x3cc == 2` and whose owner link matches (proximity fuze), not for shells.

## 2. Anti-projectile gun [V + log]
`FUN_14002f480` (called per creature from `CreatureUpdate`) runs for a weapon part that is ready (`+0x848 == 0`, `+0x80c != 0`, `+0x818 != 0`, ammo count `+0x870 >= 1`, cooldown `+0x86c == 0`). It scans all active bodies for a threat: `+0x3e0 != 0`, `penetration (+0x2e0) + explosive (+0x2dc) >= Stats(AMMO_100MM)+0x160`, not owned by this creature, distance <= 60 (`magnitudeCreatureBodyVector`), Stats flags `+0xb0` not in {0x4000, 0x8000000, 0x200000} and bit 10 clear, bearing within +-45 deg (`0.7853982`) of the gun direction and heading toward the gun (angle of the velocity > 90 deg). If one is found the gun fires (cooldown from Stats `+0x150`), and **every body within 120 units and within +-45 deg of the gun direction that has explosive != 0 (flags `& 0x405 != 0x405`, same Stats exclusions) is detonated with `vtable +0x200`** (`0x14002fb1b`); that is the `0x2fb21` rows (intact shells, hp 1, impulse 0). It then spawns "strides" particle effects. Player guns are not involved (it is a creature weapon type).
