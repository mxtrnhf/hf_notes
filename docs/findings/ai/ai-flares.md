# Why AI ships never use flares, and how to give them flares (1.163)

Status (2026-10-18: ported to hf_ai v0.2.0, see [ai-hf-ai-design.md](ai-hf-ai-design.md); qol's copy is retired once the user switches `ai_flares.enabled` over; hf_ai can write a `hf_ai_panic_*.log` trace with `log_panic`) (2026-10-16): **running in game** (fork branch `ai-flares`, `src/ai_flares.rs`; the working source is still UNCOMMITTED in the fork). Enemy AI ships drop flares and dodge missiles; since 2026-10-16 the new option `ai_flares.allies` makes AI-run ships of the player's side do the same: confirmed in play ("allied ships now use flares"). Design below was changed during implementation, see "Implementation". Tags: legend in `../../README.md`.
Addresses are 1.163 (image base `0x140000000`, the unpacked exe). Origin: roadmap item "the AI cannot deploy flares" (`roadmap.md`, AI, Tactical).

## Short answer
The AI is not missing flares or a release routine. It is missing the **trigger**. The release code is generic and runs for every creature, but the flag that starts it is only ever set by the player's input path.

## Evidence
* **AI ships carry flare launchers** [game]. 26 of the 81 vanilla designs in `Objects/Designs/*.seria` contain parts named `FLARES` (99 launchers in total). Six launchers: `Navarin`, `Intrepid Mk2`, `Gladiator`, `Fearsome`; five: `Intrepid Mk3`; four: `Wanderer`, `Wanderer Mk2`, `Titan`, `Tarantul`, `Tarantul MRL`, `Tarantul MRL Mk2`, `Tarantul ARM`, `Scarab`, `Navarin Mk2`, `Navarin Mk3`, `Jaguar`, `Gladiator MRL`, `Gladiator LANCE`, `Ballistic`; two: `Tanker`, `Talos`, `Lion`, `Jaguar Mk2`, `Hound`, `Fury`, `Flower`.
  Method: concatenate the design files, strip `\r`, count lines `m_name=FLARES` per file.
* **The part** [game] (`Libraries/OL.seria`, `m_oid=MDL_FLARES`): `m_category=8388608` (bit 23), `m_price=800`, `m_mdl_armor=5`, `m_mdl_power_need=10`, `m_mdl_sectors_type=3`, `m_mdl_sectors_threshold=0.5`, `m_weapon_load_amount=30`, `m_weapon_load_time=99999` (practically no reload), `m_weapon_rate=400`.
* **Release is generic** [code]. The per-creature update `FUN_14007eb50(creature, dt)` (`0x14007eb50`-`0x14007fce9`) is a virtual method: it has data references from a vtable (`0x14807b2d0`, `0x140354ce8`) and no direct callers, so it runs for every creature, AI included. In it:
  * `if (creature byte +0xbc0 != 0)` (Ghidra `param_1[0x178]`): for every entry in the vector at `creature +0x1408 .. +0x1410` (entries are 0x18 bytes, the launcher pointer at +8) call **`FUN_14002eed0(launcher)`**, then play the sound `flare` once if any launcher fired, then `rep_14024f4f0_Get_Profile?(creature, 0x40000000)`. The flag itself is **not cleared** here.
  * Sibling flags read in the same function: `+0xbbc` (fires the guns in the list at `+0x13a8`), `+0xbbd` (guns in `+0x13c0`), `+0xbbe` (a one-shot, cleared after use).
* **`FUN_14002eed0` (the flare release)** [code]: does nothing unless the launcher's cooldown float `+0x848` is zero, `+0x80c` and `+0x818` are non-zero (armed/powered), the count `+0x860` is at least 1 and `+0x86c` is zero. Then it decrements `+0x860`, sets `+0x86c` from a rate, and spawns one `Body` (`New(0xa40)`): lifetime `timeToLive` (`+0x2c0`) 5.0 s, **`logic` (`+0x3c4`) = `0x44c` (1100)**, layer `+0x1f0` = 0, sprite id `+0x8d8` = 5, drag `+0x1dc` = `0x3a378034` (about 0.0007, like AP shells), velocity along the launcher direction x 400 with a random angle of +-0.2 rad, and three particle effects (`smoke_FIRE.psi`, `rocket_glow.psi`, `fire_LRE.psi`). It is not built from a stats record: `explosive` (`+0x2dc`) is left at its default and `isLogicActive` (`+0x3c8`) is not set. Calling it every frame is safe because of its own gates.
* **Nothing sets `+0xbc0` for AI ships** [code, by instruction search]. The only writes to that offset I found are two 16-bit zero stores (`0x14023278e` in `displayTextOnCreature?`, `0x14024c0e3` in `FUN_14024c0b0`) and one store of a register word at `0x140072d37`; none sets the byte to 1 from an AI path. The AI tick `FUN_140062f90` and the AI weapon controller `FUN_14007a8d0` do not reference it. [The positive setter, i.e. the player's input code, was not located; the setting by search patterns with wildcards is unreliable, so this is "not found", not "proven absent".]

## Mod design (not written)
Follows the conventions in `hooks.md` (function-entry detour with version guard; or an operand/call-site patch).
1. **Hook:** a function-entry detour on `FUN_14007eb50` (`0x14007eb50`, **unowned** in the `hooks.md` ownership table), run before the original body so the flag is seen the same frame. Version guard: compare the first bytes of the function before patching.
2. **Select creatures:** AI side only. The side float at `Creature +0xad4`: negative and non-zero = AI side, positive = player's (inferred from where the difficulty byte applies, **[guess]**); has a non-empty flare list (`+0x1408 != +0x1410`); the launchers still have count `+0x860 >= 1`.
3. **Detect a threat:** a live projectile body whose target link points at this creature. A launcher writes its target link at `launcher +0x490` and its owner link at `+0x4a8` (`FUN_14002e3a0`); the link's pointer is the qword at `+0x498`, the field that function compares against the target. The global body array is `DAT_143a33c90`, count `DAT_143a51150` (the array the point-defence burst `FUN_14002f480` walks). Class filter: stats category `0x4000` (tactical missile) or `0x8000000` (strategic launch). Distance from the existing helper `FUN_1401f47f0`/the plain distance in `FUN_14020fce0` (centre to centre).
4. **Act:** set `creature +0xbc0 = 1` while the threat holds, clear it otherwise; add a reaction probability and a minimum interval so one ship does not release all 30 at once.
5. **Knobs to expose:** trigger range, reaction probability, minimum interval, number of flares per burst, which designs or classes use flares.

## Unknowns (settle in a first test run)
* What the link at `+0x498` points at for a missile aimed at a ship: the ship root, a part, or the bridge. A log line when the trigger fires answers it.
* How a missile seeker reacts to a flare body (logic `0x44c`). That is in `creatureLogic` (`0x140033b90`), which could not be decompiled in one piece [not read]. The player uses flares successfully, so an AI-released flare should behave the same.
* Whether a flaring AI ship should also manoeuvre. Not addressed by this design.
* The related roadmap bug "a proximity-fused missile colliding with flares crashes the game" is fixed upstream by highfleet-qol `enable_flare_crash_fix` ([flare-crash-hunt.md](flare-crash-hunt.md)); an AI that uses flares more often could hit it more often, so run with that fix on.

## Implementation (fork branch `ai-flares`)
* **Do not set `+0xbc0` for AI ships** [code]: the flag-on branch ends in `0x140271200`, which (in arcade battle) redraws the player's flare HUD from the ship's first launcher and resets the HUD fade timer, so an AI ship with the flag on would overwrite the player's HUD. The hook calls the release `0x14002eed0(launcher)` itself instead, so no flare sound plays yet.
* **Hook** at `0x14007f864` (the `cmp byte [rsi+0xbc0],0`, `rsi` = creature, RSP aligned) rather than the function entry: at an entry RSP is 8 mod 16, which patchy's `preserved_call` does not handle.
* **Side** [code]: `creature+0xad4` negative and non-zero = AI; confirmed by the AI-only launch limits in `FUN_14002e3a0`.
* **Threat** [code]: that function's `param_1` is the missile itself; `SetLink(param_1+0x490, target)` puts the target at `body+0x498`. Class by `0x140281e00(body+0x188)->+0xb0` equal to `0x4000` or `0x8000000` (the point-defence routine excludes exactly these). The mod accepts a link that is the ship itself or an object whose `+0xb8` is the ship, and logs which form it saw (settles the first unknown). Distance from `0x14020fb80(creature, body)`. Timers use the game clock `f64` at `0x143a119c0`.
* Unknowns that remain: how a seeker reacts to an AI-released flare, and the sound.

### Evasion (added later, same branch)
* **Where the AI steers** [code]: `FUN_140062f90` ends its steering by storing a waypoint 200 units from the ship along the wanted direction at `creature+0xbf0/+0xbf4` (`0x140064a8d`; xmm9/xmm10 = waypoint x/y, xmm12/xmm14 = ship x/y = `creature+0x1840/+0x1844`), then re-derives the direction from it, so changing xmm9/xmm10 there changes the thrust request. The ship's own velocity is `traverseLinkedListCreature_(creature)+0x130/+0x134`.
* The hook pulls that direction towards a sidestep perpendicular to the line to the nearest locked-on missile (position `body+0x128/+0x12c`, as the point-defence routine reads it), plus half as much retreat, flipping side every `jink_seconds` x 0.6..1.4. Thrust magnitude is not touched.
* Not run in game: whether the thrusters can actually turn the ship fast enough, and whether `+0x128/+0x12c` is the missile's world position in the same frame as `+0x1840` (the point-defence routine mixes it with the launcher's `vtable+0xe8` position, so probably yes).

### Boost (player Shift) and the panic evasion
* **Player boost** [code]: the control list in `setPlayerControls` (`0x1401d60ac`) maps action ids to names: `0x1000` up .. `0x1005` roll right, **`0x1006` `TITLE_CTRL_BOOST` = Shift (binding 4102)**, `0x1009`/`0x1010` fire 1/2 (LMB/RMB), `0x1015` flares (F). The input event switch (jump table at `0x140189a50`, case code `0x1401897ee`) handles boost by setting `creature+0xba8 = 2.0f` (`0x14018a76b` resets it to `1.0f`). The player control code (`0x1402a972b`/`0x1402a97de`) copies `+0xba8` into the strength field (`+4`) of the engine commands `0x66` and `0x67` (`{code, strength, ..., 999, angle}`) sent to each engine part with `0x1400533f0(part, &cmd)`. The flares action `0x1015` is the one that sets `+0xbbf/+0xbc0/+0xbc1`.
* **AI** builds the same commands on the stack in the AI tick (`0x1400656d9`..: `rbp+0x28` for `0x66`, `rbp+0x48` for `0x67`; strength at `+4` is the thrust fraction, normally 1.0 at most). The mod raises it during a panic evasion at `0x140065744`. Fuel use of a boosted engine and any extra effects (the boost HUD or sound) were not checked.
* Elevation overlay: set `elevation.hint` to `"off"` (the keys still work, nothing is drawn).

## Allied AI ships: the `allies` option (2026-10-16) [code, game]
The module decided "AI ship" with `side < 0` (`+0xad4`), so a friendly AI-run ship (side > 0, brought in by `hf_ally`) never used flares or evasion. `is_ai` in `src/ai_flares.rs` now also accepts a ship with `side > 0` and the AI flag `+0xbd4 != 0` when the config `ai_flares.allies` is `true` (default `false`); the ship the player flies has `+0xbd4 == 0` and is never affected. The three call sites (flare trigger, evasion waypoint, panic spin) are unchanged: only the test changed. Build archived as `hf_qol_fork_build/archive/highfleet_qol_ai-flares-v6-allies.dll`; the user's `qol.json` has `"allies": true` (the file was rewritten with indent 2).

## Flare curtain (hf_ai v0.5.0 to v0.5.3, 2026-10-18)
Plain words: instead of waiting for a missile to lock on, an enemy ship drops flares as soon as the player's side fires a missile, like a helicopter flooding the area with fake heat. Code: `hf_ai/src/ai_flares.rs`, pure part `curtain_math.rs`; config keys live in the `ai_flares` block of `hf_ai.json` and need `ai_flares.enabled`.
* **Launch detection** [code]: a live missile body whose target link (`body+0x498`) resolves to an enemy ship (`side < 0`). The owner link `body+0x4b0` is inferred only and not used; the first 12 launches log target / owner sides to `Modloader.log` to check it. Ghidra check [code]: `FUN_14002ff60` is called from both `AiShipTick` (`0x140065edb`) and the player launch `FUN_14018a530` (call at `0x14018a7c9`), and a launch needs an owner target, so a target always exists.
* **Rules**: one roll (`launch_flares_probability`, default 0.6 live) per ship per launch; a further launch extends the curtain; a real panic cancels it and its timers are never touched; drop cap 6 (so racks are not empty for the real panic); cooldown 6 s; enemies only. Trace events with `log_panic`: `CURTAIN_START/DROP/EXTEND/END`.
* **Defaults**: `launch_flares_interval_min/max` 0.5/1.0 s, `launch_flares_seconds` 5, `launch_flares_max_drops` 6, `launch_flares_cooldown` 6, `launch_flares_evade` 0.9, `launch_flares_evade_range` 1800, `launch_flares_boost` 2.0 (1.0 = off).
* **Versions**: v0.5.0 `29c2b90` base; v0.5.1 `93cf32b` every drop fires ALL launchers (each still obeys its own rate gate); v0.5.2 `702eb61` the ship also retreats from the launched missile (share `launch_flares_evade`, retreat plus a 0.35 sidestep, never downward when y > -250; steer CSV state shows `panic` for these rows); v0.5.3 `a70cfe7` boosts the engines during that retreat (not installed yet).
* **Not yet checked**: the `launch #N` lines in `Modloader.log` (owner side), `fl_loaded` drain of the enemies in telemetry, whether the retreat helps the ship or only looks good.
