# AI ship steering: obstacle avoidance, force law, attitude hold (v1.163), ghidra-miner, 2026-10-21

Tags: **[V]** = read in the 1.163 program (decompile plus disassembly, constants read from memory). Names: `AiShip_SteerController` `0x14006cb30` (driver states 0 and 4), `AiShip_ScanObstacles` `0x14024cc20`, `AiShip_AddObstacleNode` `0x14024ce50` (renamed 2026-10-21 from `rep_14022bc20_New`; adds one obstacle; the old name carried the 1.151 address, do not decompile that address in 1.163). `AiShipTick` `0x140062f90` carries an inlined copy of the avoidance scan (scan call at `0x140064e6f`, same parameters). **CORRECTION 2026-10-23: the force law (s3) and the per-bank clamp (s5.1) are NOT the same in the two paths**; the AiShipTick numbers are in the boxes marked AiShipTick below, they are the ones that matched logged AI commands (simulator check on 10 sessions, `hf_ml/sim/ai_cmd_check.py`).

## 1. What the avoidance sees (ScanObstacles) [V]
Called with `range = clamp(4 * |v|, 200, 800)` (v = own hull velocity, root body `+0x130/+0x134`), `minMass = 0.1 * own mass (+0x15b8)`, `maxExplosive = 500.0`.

Loop over the whole global body array (up to 15000 entries). A body is **considered** when: it is active (vtable `+0x78`), it is not the ship's own root and not owned by the same link as the ship (`body+0xb8`), its class nibble is `0xf` and it has a b2 body (`+0x178`).
A considered body is then **dropped** when all of these hold: `minMass != 0`, vtable `+0x1a8` returns 0 (meaning not read), and `returnMass(body) < minMass`. The drop is **cancelled** (body kept) when `body+0x2dc >= 500` (explosive power, so a light but strongly explosive object is still avoided). Another override keeps a body when `creature+0xd70 == 2` and bit 21 of `FUN_1400457d0(body)` is set (not read). So the avoided set is: all other ships' parts (friends and the player, one entry per part body), debris and wrecks heavier than 10 % of own mass, big explosive objects. Shells, missiles and light debris are ignored. [The earlier note had the explosive test reversed.]

Each kept body goes through `AiShip_AddObstacleNode(body, ownPos, ownRadius, list, range)` (own radius = `creature_root+0x20c`; obstacle radius = `body+0x20c`; compound bodies, class bits `0x1f`, recurse into their children):
* `d` = centre distance; `gap = d - ownRadius - obsRadius`. Kept only if `gap <= range` and `d >= 0.001`.
* Node (0x38 bytes): body, pos (+8,+0xc), velocity (+0x10,+0x14; the body's `+0x130/+0x134`, or the master's if the body has a compound master), radius (+0x18), unit vector **ship to obstacle** (+0x1c,+0x20), gap (+0x24), bearing (+0x28), shadow interval `[bearing - atan2(r, d), bearing + atan2(r, d)]` (+0x2c,+0x30), weight (+0x34, filled later).
* List is sorted by gap ascending. A new node whose bearing lies inside the shadow interval of a nearer node is **discarded** (hidden behind it); after insertion, farther nodes whose bearing falls inside the new node's interval are **deleted**. So only the obstacles visible from the ship's position survive.

## 2. Avoidance force [V]
Per surviving node: `closing = (v_self - v_obs) . dir` (positive = approaching), `t = gap / closing` (`gap <= 0` is replaced by 0.1; `closing == 0` or `t > 10` gives weight 0; `t <= 0`, i.e. receding, gives weight 0), then

`w = ((10 - t) / 10)^2` (stored at node `+0x34`).

`A = - sum(w_i * dir_i)` (pushes away). Weight factor `creature+0xc04` is set to 1.0 in the AI-ship setup (`0x140072d74`) and no other creature code writes it, so use 1.0. (`AiShipTick`'s copy omits the multiply, same result.)

## 3. Force law (translation)
**AiShipTick `0x140062f90` (the path that runs the AI engines; decompile read 2026-10-23, constants 25.0, 4.0, 10.0, 9.82, 0.1, 20.0 are decompile literals) [V]:**
* `m = creature +0x15b8`, `T1 = +0x1664`, `T2 = +0x1668`, `accel = (T1 + T2) / (m * 9.82)`, `a4 = min(accel, 4.0)`. Returns without commands if `T1 == 0` or `T2 == 0` (except a ship named "Titan...").
* `cmd_max = accel * 25.0`; but if byte `+0xc74` is set and `accel < 4.0`: `cmd_max = a4 * 40.0`.
* `s = clamp(sqrt(dist + 0.1) / 20, 0, 1)` multiplies `cmd_max` (skipped when the driver state `iVar33 == 2`).
* `ts = 10.0 / a4`; `F = ((dir_t + A) * (s * cmd_max) * m) / ts - (v * m) / ts - (0, m * 9.82)`; `A = -sum(w_i dir_i)`, `w = ((t - 10) * 0.1)^2` as in s2.
So `F = m * (s * cmd_max * (dir_t + A) - v) * a4 / 10 - (0, 9.82 m)`: a velocity controller whose desired speed is `25 * accel * s` and whose gain is `min(accel, 4) / 10` per second. This matches the simulator port `hf_ml/sim/hfsim/aisteer.py`.

**AiShip_SteerController `0x14006cb30` (driver states 0 and 4) [V; constants read: 9.82, 10, 20, 100, 0.1, 3.0]; not what the logged AI engines follow:**
* `dir_t` = unit vector from hull to waypoint (`creature +0xbf0/+0xbf4`), `dist` = distance; `s = clamp(sqrt(dist + 0.1) / 20, 0, 1)` (s reaches 1 at dist 400).
* Desired velocity `v_des = 100 * s * (A + dir_t)` (not normalised, so |A + dir_t| can exceed 1 or fall toward 0 when the avoid term cancels the heading).
* `F = m * (v_des - v) / kk - (0, m * 9.82)` with `kk = 10 / TWR`, `TWR = (T1 + T2) / (m * 9.82)`, `T1/T2 = creature +0x1664/+0x1668`, `m = +0x15b8`. So `F = (T1 + T2) / 98.2 * (v_des - v) - (0, 9.82 m)`: a proportional velocity controller whose gain scales with thrust to weight ratio (acceleration `= TWR/10 * (v_des - v)` plus gravity compensation).
* If `T1 == 0` or `T2 == 0` the function returns without sending any command (ship adrift).

## 4. Attitude hold [V]
* Gate: `creature +0x180c / I > 0.02`, with `I = Body_GetInertiaAboutOrigin(root)` (`FUN_140048440`). `+0x180c = 2 * min(+0x1684, +0x1688)` (sums of Stats `+0x100` per bank). Gate off: no torque term at all (the engines' own stabiliser, see `hull-stabiliser-engine-logic.md`, is separate and always runs).
* Commanded angle is **0 rad** (hull level, world frame); `a` = hull angle (root `+0x138`). `e = wrap(0 - a)` into `[-pi, pi]`.
* P term only, no derivative, no cap: `k = e * I / 20`, `h = (sin a, -cos a)`; **bank 1 vector += k h, bank 2 vector -= k h** (the same pair construction as the player's Q/E keys but with magnitude k).

## 5. From force to engine commands [V]
1. Bank vector = `F` (+ attitude pair). Clamp per bank, with `T` = that bank's thrust sum (`+0x1664` / `+0x1668`). **AiShipTick: `limit = T + T` (disassembly `0x14006526d`, bank 2; bank 1 the same shape at `0x140065200..0x14006522e`): if `|vec| > 2T` scale to `2T`, else if `|vec| > T` scale to `T`** [V]. **AiShip_SteerController: constant 3.0 at `0x140352804` (disassembly `0x14006d2db..0x14006d31c`): if `|vec| > 3T` scale to `3T`, else if `|vec| > T` scale to `T`** [V]. (Odd in both: values between T and the limit are cut to T. The old text applied the SteerController 3T to both paths.) (This is what the disassembly does, `COMISS` polarity checked at `0x14006d2ea` / `0x14006d31c`: values between T and 3T are cut to T, values above 3T are cut to 3T. Odd, but it is the code.)
2. Smoothing: five stored slots per bank (x at `+0xc1c + 8 i`, y at `+0xc20 + 8 i`; bank 2 at `+0xc44` / `+0xc48`), shared ring index `+0xc6c` (0..4). `out = (sum of the 5 slots + new clamped vector) / 6`; then `slot[idx] = out` (the **output** is stored, not the raw input, so it is an IIR-like filter), `idx = (idx + 1) mod 5`. Slots start at 0.
3. Per bank: angle `= -atan2(-x, -y)` wrapped to `[0, 2pi)`; strength `= |out| / T_bank` (can reach 3.0, the player's keys give 1.0, boost 2.0).
4. Commands to every engine part in the list `+0x1330`: `100` (bank 1 angle), `0x65` (bank 2 angle), `0x66` (bank 1 angle and strength), `0x67` (bank 2 angle and strength); parts act on their own bank.
5. Side effect: `creature +0x1328/+0x132c` = unit direction of `F` before the attitude term and filter.

## 6. What this does not explain / open
* **Question "what zeroes `+0x17fc/+0x1800` each tick": nothing new.** `Creature_ResetStatAccumulators` `0x140061e70` (callers `CalculateStats`, `0x140072b90`) writes 8 bytes at `+0x17f0` (covers `+0x17f0..+0x17f7`), `+0x180c`, `+0x17e4/+0x17e8`, and does **not** touch `+0x17fc..+0x1803/+0x1804..+0x180b`. Still no per-tick clearing store known; treat the logged per-tick behaviour as fact.
* Not read: vtable `+0x1a8` meaning, `FUN_1400457d0` bit 21 and the `+0xd70 == 2` mode, how `AiShipTick` picks the waypoint (`+0xbf0/+0xbf4` writes at `0x140064a8d`, `aiShipDriver` `0x140073d3f`).
* Units: velocity and positions are in game units (not Box2D metres); thrust sums are compared with `m * 9.82`, so thrust is in mass-unit x 9.82. A fit against logged AI flights is the only check of the absolute scale.

## 7. Obstacle radius, node position, and the `+0xc74` flag (2026-10-23, for the simulator's avoidance port) [V: decompile of the functions named]
* **Body `+0x20c` (radius) for a part** = writer `Body_ComputeMeshBounds 0x140054720` (stores at `0x14005472b`, `0x140054825`, `0x14005483b`): over all mesh vertices (mesh `+0x48`, count mesh `+0x50`, part-local coordinates, game units, no scale factor) take the AABB; `+0x210/+0x214` = AABB centre, `+0x218/+0x21c` = width/height, **`+0x20c = sqrt((W/2)^2 + (H/2)^2)`** = half the bbox diagonal. A mesh with fewer than 2 vertices gives all zeros. Called once per mesh set, not per tick.
* **Frame (root) `+0x20c`** = writer `Frame_RecomputeBounds 0x14011cf60` (store at `0x14011d388`): AABB over the rotated bbox rectangles of all children (rect `+0x218 x +0x21c` centred on the child origin `+0x128/+0x12c`, rotated by the child matrix `+0x8fc`), then the same: centre -> `+0x210/+0x214`, `W, H` -> `+0x218/+0x21c`, **`+0x20c = sqrt((W/2)^2 + (H/2)^2)`** (uses a 0.1-resolution sqrt cache when the square is below 10000). Called through Body vtable `+0x1f8`; the only direct caller found is `CreateFrameFragments 0x14011c40c` (break-up); other `+0x1f8` call sites (`handleBodyMesh? 0x14001c469`, `FUN_14004eab0`, `FUN_14011bdd0`, ...) were not traced, so **whether a child's death alone triggers a recompute is NOT established**; it is certainly recomputed when the frame is rebuilt by break-up. Units: game units (not b2 metres).
* **`AiShip_AddObstacleNode 0x14024ce50(body, ownPos, ownRadius, list, range)`**: skips the body if `+0x1f0 == 0` (collision layer 0). `pos` = the bbox CENTRE `(+0x210, +0x214)` mapped to world by Body vtable `+0xe8` (NOT the origin `+0x128/+0x12c`); radius `r = +0x20c`; `d = |pos - ownPos|`; `gap = d - ownRadius - r`; kept only if `gap <= range` and `d >= 0.001`. A compound (`class & 0x1f == 0x1f`) that passes that test for ITS OWN centre/radius is not added itself: it recurses into every child in the list at `+0x100` (each child redoes the same test with its own centre and radius, same ownPos/range). A non-compound body becomes a node: velocity = master's `+0x130/+0x134` if the master (`+0x88`) is a compound, else its own; unit vector = `(pos - ownPos)/d`, bearing etc. as in s1.
* **`+0xc74`** is one of the three AI ammo-choice flags (`+0xc74`, `+0xc75`, `+0xc76`), written ONLY by `AiRerollAmmoFlags 0x140079810` (stores `0x140079862` = 0, `0x140079af9` = result) and zeroed by the constructor (`0x1400730d3`). Every 30 s (timer `+0xc78`, reset to 30.0 `0x41f00000`) while the AI has a ship target (`+0xb00`, class check `& 0x2f == 0x2f`): `+0xc74 = random(0,1) < ((target +0x15bc / target +0x15b8) * 2)^2` (so certain when the ratio >= 0.5; the numerator `+0x15bc` is not identified, `+0x15b8` is mass). It is cleared to 0 when the target is null or not a ship. So it is set at random per ship and per 30 s window for ANY AI ship (allies too), not by ship type. Uses: AP-ammo selection in `AiWeaponController`, and the `cmd_max = min(accel, 4) * 40` branch of `AiShipTick` (only when `accel < 4`).
