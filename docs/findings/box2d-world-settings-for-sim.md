# Box2D world settings the game uses in combat, as a checklist against pybox2d 2.3.2 (ghidra-curator, 2026-10-22, answering the simulator's fast-spin question)

Tags: **[V]** read in the 1.163 program today, **[doc]** already documented, see the linked file, **[open]**. Most of this was known; this file collects it in one place and adds what the 2026-10-22 pass checked. Detail: [box2d-physics-setup.md](box2d-physics-setup.md), [box2d-struct-layouts.md](box2d-struct-layouts.md), [box2d-function-map.md](box2d-function-map.md).

## 1. The step [V]
`SomethingPhysicTask` 0x140286380 calls `b2World_Step(SuperBig, dt, 10, 10)` at 0x14028658a (`R8D = R9D = 10` set at 0x14028657e / 0x140286584): **10 velocity and 10 position iterations**. `dt = 1.0 / CORE_FRAMERATE`: the numerator is the constant 1.0f at 0x1403524d8, the divisor is the app property `CORE_FRAMERATE` bound to 0x1403c0de4 (initialised 50.0, set through `InitializeAppProperties`), so **dt = 0.02 s, always, one step per frame, no sub-stepping, never the measured frame time** (the thermal pass uses the frame dt `time_related_global_`, the physics does not). Only a changed `CORE_FRAMERATE` setting would change it.
Order inside a frame (see player-thrust-keys-and-engine-heat.md section 10): `SomethingPreTask` -> `SomethingPhysicTask` (per body `Body_PreStepUpdate` [Frame drag], `b2World_Step`, `Body_SyncFromB2`) -> input task (engine forces into the b2 accumulators) -> AI task -> game task. **A thrust force added in frame k is integrated by the step of frame k+1**, together with the drag force computed at the start of that step; the accumulators are cleared at the end of `b2World_Step` (world flag 4). The force is constant over the 10 iterations as in stock.

## 2. World setup [V]
`SuperBigConstructor` 0x14031a610: **gravity = (0, 0.05 x 9.82) = (0, +0.491) b2 units/s^2** (+y is down = 9.82 game u/s^2; never changed after creation: the only writer of world+0x19338 is the constructor); allowSleep = 1; flags word +0x1935c = 0x1000101 = **warmStarting 1, continuousPhysics 1 (TOI is run, `rep_1402f0140` called from `b2World_Step`), subStepping 0**, +0x1935f = 1 (step complete); world flag +0x19298 = 4 (clear forces after the step). Stock 2.3 constants, all read: maxTranslation 2.0 per step (squared 4.0), maxRotation pi/2 per step (= 78.5 rad/s at dt 0.02), linearSlop 0.005, angularSlop 2 degrees (0.0349066), maxLinearCorrection 0.2, maxAngularCorrection 0.1396, Baumgarte 0.2, velocity threshold 1.0 (restitution bias only for relative normal speed < -1.0), block-solver condition number 1000 (Box2D 2.3.1 and later), time to sleep 0.5, linear sleep tolerance 0.01, angular sleep tolerance 2 degrees, polygon radius 0.01, tree fat margin 0.1, friction = sqrt(fA*fB), restitution = max(rA, rB). The code is a stock-shaped 2.3.x build with the QueryPerformanceCounter profiling added and one change: the weld joint (below). Damping in `b2Island_Solve` is `v *= clamp(1 - h*c, 0, 1)` (the 2.3.x form, **not** `1/(1 + h*c)` as an older line in box2d-physics-setup.md says; the difference at c = 0.05, h = 0.02 is 5e-7 per step). Gravity is applied as stock: `v += h * (gravityScale * g + invMass * F)`.
**Ships feel gravity**: `Body_PreStepUpdate` adds a counter-force `(0, mass x -9.82 x Body+0x1e4)` only when `+0x1e4 != 0`; for a ship Frame `+0x1e4` is 0 at creation (flares and particles use 1.0, shells 0.325 to 1.5), so a hull has the full 9.82 u/s^2 pulling down. [doc] hull-rotation-behaviour.md notes the coast test with gravity and drag matching.

## 3. Per-body defaults [V, doc]
b2BodyDef (`Body_CreateB2Body` 0x14004b330): type dynamic (2) when `Body+0x1d0` (density) > 0 else static; linearDamping = angularDamping = **0.05**; allowSleep true, awake true, **fixedRotation false**, active true, gravityScale 1.0, **bullet = Body+0x1fc** (shells; ship Frames not flagged as far as read). Fixture (`Body_CreateFixture` 0x14004b530): one b2PolygonShape per part (at most 8 vertices, part-local to Frame-local, x 0.05), radius 0.01, **density = 0.05 x min(w,h) x m_density**, friction `Body+0x1d4` (default 0.6), **restitution 0.001**, filter category 1 / mask 0xFFFF / group 0 (everything is decided in `b2CFilter::ShouldCollide` 0x1402858c0), no sensors; SetMassData is never called. Mass in game units = b2 mass / 0.05^3, inertia /0.05^5. Forces: `Body_AddForceAtPoint` scales the point by 0.05 and the force by 0.05^4 (so torque by 0.05^5), `Body_AddForceAtCenter` likewise; `Body_AddTorque` writes `w += torque * 0.05^5 * invI` directly.

## 4. Joints [V, doc]
`Joint_CreateB2Joint` 0x140193a10, kinds: 0 = distance (`b2DistanceJointDef_Initialize`, **frequency 10 Hz, damping 10**: the leg joints), 1 = revolute, 2 = weld (type 8), 3 = type 10. **Revolute (swivel engines, legs, turrets):** collideConnected false, enableLimit Joint+0xf4 / referenceAngle +0xf8 / lower +0xfc / upper +0x100 (swivel engines: **no limit**, hull-stabiliser-coupling.md), enableMotor +0x104, **maxMotorTorque +0x108 and motorSpeed +0x10c used raw, not scaled by 0.05 powers** (`Engine_ServoUpdate` sets torque = part mass/100 = 300.76 and speed = `wrap(cmd - angle) * P * Stats+0x108 * P`, linear, via `Joint_SetMotor` every tick; the motor speed is relative, `wB - wA`). **Weld joint (antenna chains only): modified, frequency 0, damping ratio 10, plus a "linear mass scale" 6.0 stored at joint+0x8c (def+0x44) that stock lacks** (box2d-struct-layouts.md); no engine or hull-structure weld exists on the ships checked.

## 5. Anything that clamps or rewrites ship velocity [V, doc]
None found per frame: no max-angular-speed clamp, no damping applied in game code, no spin limiter or gyro (static-engine-force-path.md section 4, hull-rotation-behaviour.md). The only clamps are Box2D's: maxRotation pi/2 per step (78.5 rad/s, so not active at 5-9 rad/s) and maxTranslation 2.0 b2 per step (40 game u/step). Writers of the Frame angular velocity: `b2Island_Solve`, `Body_SetAngularVelocity` (fragments, level code, `CreateFrameFragments` on break-up: random spin on spawned fragments), `Body_AddTorque` (rocket and aircraft PD guidance, level scripts, an AI override); none is a per-frame ship control. Sleeping: an island whose bodies all stay under 0.01 b2 m/s and 2 deg/s for 0.5 s is put to sleep and its velocities are zeroed (`b2Island_Solve`), which only matters on the ground.

## 6. Differences to check in the sim (pybox2d 2.3.2)
1. dt exactly 0.02, **one** step per frame, 10/10, warm starting on, **continuous physics (TOI) on**, sub-stepping off: confirm pybox2d defaults (`doSleep`, `warmStarting`, `continuousPhysics`).
2. Gravity (0, +0.491) in b2 units with y down and gravityScale 1.0 on every body, no counter-force for hulls.
3. Damping 0.05 / 0.05 with the clamp form, **not** zero damping as the sim has (the hull spin loses 5 % per second; the sim's "no damping" matters for slow decay, not for the fast windows).
4. The length scale 0.05 and the force, torque and mass scalings of section 3; swivel motor torque 300.76 and speed unscaled.
5. The Frame quadratic drag `F = -v_hat * A * min(W,H) * |v|^2 * 1.29 * 0.5` applied at the Frame point +0x210/+0x214 before every step (a torque about the COM).
6. One frame of latency: the thrust force added after step k is integrated in step k+1; the engine command angle is built from the hull angle that `Body_SyncFromB2` stored at the end of step k.
7. Fixture shapes are single convex polygons per part (at most 8 vertices) with radius 0.01, friction 0.6, restitution 0.001; hull inertia comes from the fixtures only.
8. Nothing in the game limits the hull spin below 78.5 rad/s; if the sim's windows at 5-9 rad/s have thrust-side residuals, the candidates in code are the engine command and force latency (point 6), the servo lag of the swivel engines at that spin (`g = cos(cmd - world angle)`, the overheat lock, the cone blocking `+0x848`, and the 0.01 thrust penalty under `+0xbc4 < 0.5`), not a world setting.
