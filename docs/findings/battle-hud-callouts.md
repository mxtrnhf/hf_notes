## 5. The callout colours are set by the per-frame TITLE tint pass (2026-10-25) [code: decompile of `0x1402a2a80`; return addresses from the rel.44 colour log]
Return addresses resolved (RVA + `0x140000000`): `0x1402a2c02`, `0x1402a2d25`, `0x1402a2eee` are all inside **`0x1402a2a80`** (Ghidra name `displayGameBootScreen`, wrong; renamed `Gui_TitleElementsTintPass`, plate comment added); `0x1402e078b` is the generic sprite-draw function at `0x1402e02c0` (body to `0x1402e082f`, stale name `..floorf`); `0x14016f155` is `setfield_0x1020SideEffects?` `0x14016f120`; `0x1402e96f5` is inside `setupVideoTask?` `0x1402e7760`.
**`0x1402a2a80` runs every frame (also in battle).** It first draws the `title_logo` / `TITLE_OSIP` sprites tinted `0xA8FC00` with an alpha fade (boot screen duty), then it **gathers every GUI element named `"TITLE"`** (`memcmp("TITLE", &vec, 0)`; these are the HUD title/callout blocks) and, per element `g` (a GUI object, `plVar1`):
* **Normal elements** (`g != DAT_1403c0d58`): sets `g+0x11f*8 = alpha`, then for each child sprite in the vector `g+0x8c0 .. +0x8c8` writes the sprite colour floats `sprite+0x118/+0x11c/+0x120/+0x124` (R, G, B, A, each /255): **lime `(0xA8, 0xFC, 0x00)` when `g+0xc08 == 0`, red `(0xDD, 0x27, 0x27)` when `g+0xc08 != 0`** (alpha 1.0), then `g+0xa8c = 0xFFA8FC00` (the text/tint colour member), then the virtual calls `+0x240` and `+0x2c8` (re-render) and restores alpha to 0.1. This is the **yellow-green callout of your screenshot**; red is the same element with the flag set.
* **The special global element `DAT_1403c0d58`**: child sprite colour **`(0x76, 0x49, 0xFF)` (blue-violet) when `g+0xc08 == 0`, red `(0xDD, 0x27, 0x27)` otherwise**, alpha = `pulse * fade * g+0x98c` (pulse from the half-second timer `fVar20`), `g+0xa8c = FUN_1400494b0(0x7649ff)` (ARGB build) and, when the half-second tick fires and `g+0x180 != 0`, plays `alarm_small_07`. `DAT_1403c0d58` is read by many HUD/map functions (cursor/selection style code: `UpdateZoom`, `World_ThermalPass`, `renderMapProjectiles??`, `SomethingInputTask`...): it looks like **the player's own highlighted/selected element**, which is why `0x7649FF` appears for "the player's own" marks.
So the game's colour set for these HUD elements is: **lime `0xFFA8FC00` (default), red `0xFFDD2727` (alarm/hostile flag `g+0xc08 != 0`), blue-violet `0xFF7649FF` (the special own/selected element)**. Of your candidates (`0x7649FF`, `0x19FFFF`, `0x00E4FF`): **`0x7649FF` is the one this HUD code itself uses as the "own" blue**; `0x00E4FF` is the result-screen friendly cyan (section 2); `0x19FFFF` I did not find in code.
**How the colour is chosen:** by the flag in the GUI element (`g+0xc08`) and by identity with `DAT_1403c0d58`, **not by ship side**. Nothing in this pass looks at a creature's `+0xad4`. To make a callout blue for allied ships, the hook must know the element's body. Lead: GUI elements keep their linked object at **`gui+0x178`** (`ClickFunc` reads `ship = gui[0x178]` for `AMMO_SELECT`; `FUN_1400211a0` links the part with `SetLink(part+0x9c8, gui)` and gives the GUI its anchor with `vtable+0x358(gui, part, "", "gui_mil")`); I did not verify that the TITLE callout stores the part/ship there.
**Hook options (untested):** (a) post-pass: detour the return of `0x1402a2a80` (or hook `0x1402e0bd0`, the per-sprite draw it calls as `FUN_1402e0bd0(sprite, g, g+0x964, g+0x95c)`) and, for each TITLE element whose linked body's owner has `side * player_side > 0`, rewrite the child sprite colour floats to the blue before drawing (`RGB 0x76,0x49,0xFF` = `0.4627, 0.2863, 1.0` in the float slots `sprite+0x118..0x124`); (b) per element immediate patches are not per ship, so they cannot do it. The sprite colour setter you logged (`0x140172ae0`, from `0x1402e078b` x144 = the `0x1402e02c0` draw) takes the colour from those float slots, so rewriting the slots before `0x1402e02c0` runs is the cleanest, and `0x1402e0bd0` receives `RCX = sprite`, `RDX = g` (the GUI element) as arguments, which gives the hook the element at the moment of drawing.

## 6. Resolved: the yellow-green hover callout is the TADS damage popup (2026-10-25) [code: decompile of `0x1402a19c0` and `0x14028b560`]
**Correction to section 5:** `Gui_TitleElementsTintPass` `0x1402a2a80` is the boot/title logo pass (its `a8fc00` draws at `0x2a2c02/0x2a2d25/0x2a2eee` are the title logo and `TITLE_OSIP` text with an alpha that is 0 in battle). **The callout = a per-ship "damage popup" list:**
* **Container:** global `std::list` at **`DAT_147fc6898`** (sentinel pointer; element count `_DAT_147fc68a0` = `0x147fc68a0`), list node `+0x10` = **entry** (`Link`, 0x58 bytes). * **Line record (0x50 bytes):** `+0x00` std::string key (the module/label key, for example the part name), `+0x20` std::string text2, **`+0x40` int amount (the "-N" count)**, `+0x44` int, **`+0x48` int = line colour (ARGB) from the caller**, `+0x4c` int = state/flag (`>= 300` makes the colour pulse via a 1 Hz alpha).

Colours:
