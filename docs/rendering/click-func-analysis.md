## Corrections to the older notes [code]
* **Name:** the 1.163 function is `!ClickFunc` at `0x14012f120` (the `!` is part of the stored name; use it in MCP calls). It does decompile (about 49 s, payload limit 1000 MB); the older "decompile fails" remark applies only to the default tool settings.
* **4th argument is a float in XMM3, not R9:** `0x14012d157 MOVSS XMM3,[RBX+0xa80]`, `MOV R8D,ESI`, `MOV RDX,RBX`, `MOV RCX,RDI`, `CALL 0x14012f120`. So the signature is `ClickFunc(ctx, gui, int button, float value)` with `value = gui+0xa80`, used as a list index. R9 is not an argument (a probe that logs R9 sees its own trampoline value).
* **The element name is a `std::string`, not a C string:** pointer at `gui+0xa40`, length `+0xa50`, capacity `+0xa58`; text is inline only while capacity is at most 15. For longer names `+0xa40` holds a heap pointer, which explains the garbage names in older probe logs.
* **`HELLO_OMAR_1` is not an element name:** the compare at `0x140136b47` is for `"OMAR"` (an NPC class); `HELLO_OMAR_1` is a dialog string loaded at `0x140136b5e` for `formDialogStrings` [analysis]. The element catalogue `docs/data/clickfunc-elements.tsv` took the nearest preceding literal instead of the `RDX` argument; the workspace's `clickfunc_1.163.strings.tsv` is the corrected catalogue.
* **Counts:** 256 compares, 251 unique literals; 297 distinct direct callees; the two `.pdata` data references at `0x14807f3c0/c8` are not callers [analysis].
* **One click can reach ClickFunc twice for a code reason too:** the `GL_LIST_BUTTON` prologue branch (`0x14012f238`) writes the child index and calls ClickFunc recursively on the child [analysis].

## "Editor array" helpers are STL [code]
`diffArrayDivBy24` (`0x1400530e0`) is `(end - begin) / 0x18` and `multElementsBy24` (`0x1400188e0`) is `begin + index * 0x18`: `std::vector::size()` / `operator[]` for **0x18-byte elements** (Link, and also the 0x18-byte battle creature list records), not editor-specific. Renamed `Vec24_Size` / `Vec24_At`. `FUN_14012a4b0` is the `vector<Link>` copy constructor, `FUN_140129f40` a bidirectional iterator advance, and the three `push_back` helpers are `0x140165a00` (8-byte elements), `0x1401659c0` (Link) and `0x140165940` (0x58-byte deck entries, `DAT_143a15930`). The `0x140129f70..0x14012a590` family is `std::map`/`_Tree` insert machinery [analysis].

## Facts worth keeping [analysis unless marked]
* **Difficulty is two bytes on the Profile [code, `PRESELECT_HARD` writes at `0x1401373ec`, `0x140137498`, `0x140137559`]:** `Profile+0x164` = easy flag, `+0x165` = hard flag (normal 0/0, easy 1/0, hard 0/1). This answers the long-open "what is `Profile +0x164`" of the AI-ammo spawner chain ([findings/ai/ai-tick-patch-sites.md](../findings/ai/ai-tick-patch-sites.md), STATUS): it is the difficulty byte, not an unknown. `PRESELECT_HARD` cycles the three states.
* **Spasm codes:** `part+0x370` is the saved vector `m_spasmcode` (serializer key at `0x140353410`, read [code]); the editor buttons edit it: `ED_PROP_LEFTTHRUST` {100, 0x66}, `ED_PROP_RIGHTTHRUST` {0x65, 0x67}, `ED_PROP_LEG` {400, 0x19a} (and toggles logic `+0x3c4` 400/0), `ED_PROP_CANNON_01/02` {200, 0xd2} (logic 200/0xd2). This matches the bank pairs {100,102} = bank 1 and {101,103} = bank 2 of [../findings/player-thrust-keys-and-engine-heat.md](../findings/player-thrust-keys-and-engine-heat.md).
* **Intel:** `Profile+0x364` is the saved `m_intel_data` (key at `0x14035ee70`, read [code]), the intel-point counter spent at the intel terminal (costs 3/2/1).
* **Editor flag bits:** `part+0x1f0` low 12 bits = layers `ED_PROP_LAYER1..12`; `part+0x9b0` bits 0..3 = floor `ON/AUX/SUP/EXTRA`; `part+0x1c0` `0x1801` = cannon marker; slot element `+0xc00` = type bitmask (bits 0..11 = `ED_SLOTS_TYPE1..12`, `0x200000` M, `0x400000` S); `part+0x3c8` generic logic flag; `part+0x7b0` leg marker. Complete tables: `editor-flags.md` in the workspace.
* **Map move:** `MAP_MAP/LOCATION/ESCADRA/CRAFT/MISSILE` write `PLAYER_ESCADRA+0x2d0` (target position), `+0x2d8` (target Link), `+0x461 = 1`, `+0x368 = 9000.0f`, `+0x464 = 1.0f`, then press `MAPMODE_THRUST_SLIDER`; `UpdateStrategicFleet` consumes them (move start `0x1401131a5..0x1401131c3`, clears at `0x140112dae`, `0x140112de7`, `0x1401133b2`).
* **Economy:** `BUY_BUY` (`0x140138564`): `delta = slider - owned`, price `*(int*)(ammo+0x170)`, `Profile_SubtractCash(profile, price*delta, 0)`; `FUEL_BUY_SLIDER` compares `[gui+0xc0c]` with `CURRENT_LOCATION+0x274`. Sell ship `SELL_YES` -> `sellShipButton` `0x140252270`.
* **Shipworks:** fast-repair cards are the vector at `ship+0x19b8`, count `+0x19c0`, capped at 4 by `SAVE_DESIGN_OK`.
* **Open (the workspace's own list):** the editor object behind `FUN_1400db0b0` (`+0x4f0`, `+0x8c8` arrays), the element layout of `Profile+0x560` (missile inventory), the group object at `creature+0x158` used by the hot-seat path, the several meanings of `DAT_147fc6fc4`, whether the `MAP_*` move behaves identically for every fleet type (needs a live map test).
