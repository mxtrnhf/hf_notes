# Porting a mod between 1.151 and 1.163 (guide)

For anyone moving a hook or a data patch from one build to the other. **No mod has been run on 1.151**: all five of our mods are 1.163-only. Only the explosion routine and the Body damage slot were hooked and observed live there (`hf_probe` 2.4, [findings/explosion-damage-1151-vs-1163.md](findings/explosion-damage-1151-vs-1163.md)); every other 1.151 value below comes from reading logdot's annotated 1.151 program next to the 1.163 one. Tags: legend in `../README.md`. Reference tables with the evidence: [version-differences.md](version-differences.md); hooking techniques and site ownership: [hooks.md](hooks.md).

## 1. What actually changed (read this first)
| Area | 1.151 | 1.163 | Effect on a mod |
|---|---|---|---|
| Code addresses | base `0x140000000` | same base, but code **moved**, by an amount that varies per region (see the anchor list in section 4) | no hook address can be reused; find each site again |
| `Body` (ship part) size | `0xa08` | `0xa40` | field offsets shift by zone: 0 up to `0x1f8`, +4 at `0x20c`, +0x10 from `0x2a8`, **weapon block differs inside** (saved keys +0xc, runtime fields +0x14), +0x30 from the floor fields, +0x38 at the tail |
| Weapon fields | single `weaponAmmoAmount` `0x84c` decremented by `FireGun` | saved reserve `+0x858` (`m_weapon_ammo_amount`), runtime loaded count `+0x860` (decremented), ammo index `+0x850` | ammo logic cannot be ported by offset arithmetic |
| `Profile` vectors | fleets `+0x1b0`, missiles `+0x1e0`, map crafts `+0x228` | `+0x1f8`, `+0x228`, `+0x270` | every walk over a map-object list |
| `Escadra` (fleet) | count `+0x4e8`, range `+0x4f0`, missile cooldown `+0x508`, aircraft cooldown `+0x50c` | `+0x4ec`, `+0x4f4`, `+0x50c`, `+0x510` | salvo-style cooldown patches target a **different** field per version |
| Stats record | `0x180` bytes | `0x188`: fields from `0x12c` inserted (`sectors_shift`), `0x16c` (`cluster`) | +4 after `0x12c`, +8 after the cluster field |
| `Ammo` record | `0x168` | `0x188` (new `shell_enemy` string, float `ttl` at `+0x16c`) | stride of `AmmoDefList`; shell lifetime now per ammo |
| HGE interface table | `Resource_Load` is slot 17 | an extra "load file" slot at 17, so slots from 17 are **+8** (`Random_Float` `+0x108` to `+0x110`) | any call through `*HGE` |
| Body vtable | damage slot `+0x208` | `+0x210` | direct vtable calls |
| Map speed | `25 * TWR` | `50 * sqrt(TWR - 1)` (a `powf` call) | the speed mod's mechanism does not exist in 1.151 |
| `FireGun` | contains the 360-sector gun-arc block | no sector check (highfleet-qol restores it) | arc mods are 1.163-only by design |
| Input | DirectInput8 | SDL2 | input hooks |
| Content | no skirmish | skirmish/PVP levels, captains, `SavesSkirmish/`, new ships, harpoon, KAZ ammo | libraries and level lists differ |

Gameplay differences that matter to players on 1.151: shell lifetimes (100 mm 10 s to 4 s, 130 mm 10 s to 7 s, 180 mm 10 s to 30 s), warheads, incendiary power, the close-range AI weapon cutoff (1.163 only). Full list: [findings/ammo-1151-vs-1163.md](findings/ammo-1151-vs-1163.md), [findings/ai/ai-tick-patch-sites.md](findings/ai/ai-tick-patch-sites.md).
Explosion damage also changed: Zenith-class warhead 200 to 300, first armored part in the blast chain x2 to x4, ordinary part cost flat 5 to `maxHP/20`: [findings/explosion-damage-1151-vs-1163.md](findings/explosion-damage-1151-vs-1163.md).

## 2. Guard every build (non-negotiable)
* Export `version(const char*)` and accept only the strings you tested (`Steam 1.151`, `Steam 1.163`, `Gog 1.163`); **`init()` still runs when `version` returned false**, so check again inside `init` ([setup.md](setup.md)).
* Compare the exact bytes you are about to change (about 24-40 bytes around the site) and do nothing, with a log line, if they differ. This is what protects against an unknown build and against a future update.
* Never patch a pooled constant (`100.0f`, `30.0f`, `1.0f` are shared by dozens to hundreds of sites): repoint the instruction's operand ([hooks.md](hooks.md)).

## 3. Porting one site, step by step
1. **Say what the site does**, in one sentence, from the 1.163 side (the findings notes usually have it: for example "the cooldown immediate in the map launch consumer").
2. **Find the 1.151 function.** Open `Highfleet.exe.unpacked.exe v1.151` in the shared project. logdot named about 875 functions there, so search by name first (`initProfileMissiles_`, `TryLaunchAiAircraftGroup`, `FireShell`, `DefineAmmos`, ...). The names that map to 1.163 functions are in the table in [version-differences.md](version-differences.md). If the name is missing, search by a string or a constant the function uses, not by fuzzy similarity: scores below about 0.9 are unreliable ([setup.md](setup.md)).
3. **Decompile both and compare structure**, then locate the exact instruction. Expect the same shape with shifted offsets.
4. **Translate offsets with the zone tables**, then **confirm each one in the 1.151 code** (a field read in the same role in the same statement). The tables are reliable at the anchors listed there and by zone elsewhere; the weapon block, the bool cluster `0x86a..0x87c` and the lighting/tail fields are the known weak spots.
5. **Read the bytes** of the 1.151 site (`read_memory`), write them into your guard, and build a separate 1.151 hook table. Do not try to share one address table between versions.
6. **Test on that build.** A passing 1.163 test says nothing about 1.151.

## 5. What each of our mods would need
None has been tried on 1.151; this is the porting work, not a promise it works.
| Mod | 1.163 mechanism | Porting notes |
|---|---|---|
| highfleet-elevation | polls the editor's held-part pointer (global `0x1403c0d88`), writes `m_floor_type` `+0x9b0` and `m_floor` `+0x9b8` | globals have new addresses; floor fields are `+0x980` / `+0x988` by the 1.151 struct and the zone table (+0x30); editor-active flag also moves |
| highfleet-speed | redirects the `call powf` at `0x140080699` | **no `powf` curve in 1.151** (`25 * TWR`); a different patch, or none (1.151 already has the classic curve) |
| highfleet-multicharge | detours the combat AA launch `0x14002e590` / `0x14002e3a0` (not the Zenith launch `0x14002ff60`) and the map launch `0x1400eced0`; swaps part ids; uses stats index `+0x188` (same offset in both) | find the 1.151 twins; the part-id string capacity rule and `+0x188` carry over; stats-record offsets differ |
| highfleet-salvo | data patch of the `300.0` immediate at `0x1400ed598`+6 (`mov [rdi+0x50c]`) and the level loader `0x14025afd0` | in 1.151 the field is **`+0x508`** and the consumer is `initProfileMissiles_`; the engagement lists and `DAT_143a11902`-style globals need re-finding |
| highfleet-refuel | repoints three `MULSS` sites (`0x14011521f`, `0x140115240`, `0x14011529c`) inside the fleet update | sites sit in `UpdateStrategicFleet` (`0x14010c3a0` in 1.151); fleet fuel fields `+0x498` / `+0x4a0` are early fleet fields (shifted by about +4 elsewhere), unverified |
| highfleet-qol (logdot) | restores gun-arc blocking in `FireGun` | **already present in 1.151's `FireGun`**, so not needed there |

## 6. Data patches (libraries, saves)
* `OL.seria` / `parts.seria` are text, but 1.163 adds stats fields (`m_mdl_sectors_shift`, `m_missile_explosive_cluster`) that 1.151 does not know; keep a variant per version if you add them ([formats.md](formats.md)).
* Level lists and save layout differ (skirmish). Do not share a `Saves/` folder between versions.
* Ammo values live in code (`DefineAmmos`), not in `OL.seria`; changing them means a code patch in either version ([findings/ammo-1151-vs-1163.md](findings/ammo-1151-vs-1163.md)).

## 7. Known weak spots (verify before relying)
* Body tail (lighting, `aircraftLogic`, flags) and the bool cluster are mapped by zone only.
* Body `+0x7f8` is fuel (double, live-confirmed), `+0x800` `m_mdl_fss` (float), `+0x804` `m_mdl_crew` (int); only the crew half is unconfirmed live (it read 0 on every part) ([version-differences.md](version-differences.md)).
* Escadra and Creature remaps beyond the fields in the tables.
* Everything about 1.151 in this guide is read from code, except the explosion routine and damage slot, which `hf_probe` 2.4 observed live on Steam 1.151; no mod has been run on 1.151.
