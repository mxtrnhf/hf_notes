# `rep-audit-2026-10-29.tsv` — consolidated `rep_*` audit (batch 6)

One row per `rep_*` function the batch-6 re-match agents inspected. Columns
(tab-separated, no quoting; do not add tabs inside a field):

```
addr<TAB>old_label<TAB>verdict<TAB>new_name_or_identity<TAB>evidence
```

* `addr` — function entry, hex with `0x`.
* `old_label` — the `rep_...` name as it was before the pass (the stale
  embedded target, e.g. `rep_140057220_..._sqrtf`).
* `verdict` — the values actually used by the four agents: `renamed` (body
  proved a new name, applied and plated), `stale label` (body contradicts the
  embedded label; recorded, not renamed) or `unreadable` (bytes could not be
  hashed).
* `new_name_or_identity` — the applied name, or the identified-but-unapplied
  identity, or `-`.
* `evidence` — the shortest decisive proof (hash twin, callee, string, vtable
  slot, RTTI).

Rows are not de-duplicated: the same address can legitimately appear twice if
two agents looked at it from different sides (e.g. an out-of-range note plus the
owner's own verdict). Resolve those by keeping the verdict of the agent that
owns the address.
