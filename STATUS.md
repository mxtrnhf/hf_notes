* **`enabled` rule (logdot's review of #19):** only `elevation` and `ai_flares` may have an `enabled` flag; every other section defaults to vanilla. The flag crept back into refuel and speed once, from branches cut before the review.
* **Build break (found 2026-10-14, fixed):** `highfleet-qol` depended on `highfleet-rs` by git URL with no pinned revision and `Cargo.lock` was gitignored, so a fresh build resolved the newest `highfleet-rs`. Its commit `cfa6ae28` removed `Ammo::unknown_180h`, which `src/plane_guns.rs:271` still used. PR #18 was closed; PR #21 tracks the lockfile, and the bundled `qol/` copy pins `3f6b54b3`.
* **Modloader quirk:** the modloader README says the release zip is `Artifacts.zip` and yields both `bass.dll` and `bass.dll_`. v4.1.0's `Modloader.zip` has only the loader `bass.dll`, so users must rename the original `bass.dll` to `bass.dll_` themselves.
* Standalone repos are the pre-merge versions. Salvo is postponed. `hf_probe` and `hf_draw_test` are debug-only and not released.

## Data and working rules
* Combat telemetry is a local development feature: it is not in the public hf_ally builds since v0.14.3, but the code and docs are still maintained locally, and older `highfleet-allies` commits/releases (up to v0.14.2) still contain the full telemetry build. Sessions are in the local `tuning_telemetry/` folder; the local `REVIEWED.tsv` ledger lists analysed sessions, and unlisted ones in `Modloader/logs` are new. The user labels ships (Shipworks designs are named `TestProject`). Format: [docs/findings/ai/ai-telemetry.md](docs/findings/ai/ai-telemetry.md).
* Install DLLs and change game configs only when asked; keep a `.bak`. Long open questions: [docs/open-questions.md](docs/open-questions.md).
